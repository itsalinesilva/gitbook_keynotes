Lesson 2 - Segurança com mentalidade

​Vamos dedicar um pouco de tempo para discutir ​um conceito que ajudaria você ​em toda a sua carreira de segurança: ​ter uma mentalidade de segurança. ​Nos cursos anteriores, discutimos várias ameaças, riscos ​e vulnerabilidades e como eles podem impactar ​as operações organizacionais e as pessoas ​atendidas por essas organizações. ​Esses conceitos são considerações fundamentais ​quando se pensa em ter uma mentalidade de segurança. ​Você terá que reconhecer não apenas o que está defendendo, ​mas contra o que ou contra quem está se defendendo. ​Por exemplo, é importante ​reconhecer os tipos de ativos que são ​essenciais para manter as ​funções de negócios de uma organização, ​juntamente com os tipos de ameaças ​, riscos e vulnerabilidades que ​podem impactar negativamente esses ativos. ​E é disso que se trata ter uma mentalidade de segurança. ​Uma mentalidade de segurança é ​a capacidade de avaliar riscos e constantemente ​procurar e identificar ​a violação potencial ou real de um sistema ​, aplicativo ou dados.\
​No início do programa, ​discutimos ameaças, riscos ​e vulnerabilidades decorrentes de ​ataques de engenharia social, como phishing. ​Esses ataques são projetados para comprometer ​os ativos de uma organização para ajudar ​o agente ou agentes da ameaça a obter ​acesso a informações confidenciais. ​Usar nossa mentalidade de segurança pode ​ajudar a evitar esses tipos de ataques. ​É importante que estejamos constantemente ​atualizados com os tipos de ataques que estão acontecendo. ​Para fazer isso, é bom desenvolver o hábito de buscar ​informações sobre ​as ameaças ou vulnerabilidades de segurança mais recentes. ​Ao fazer isso, novas ideias para ​proteger os dados da empresa podem vir à mente. ​A segurança é um objetivo diário ​de todas as equipes de segurança do setor.\
​Portanto, ter uma mentalidade de segurança ajuda os analistas a ​se defenderem contra a pressão constante dos atacantes. ​Essa mentalidade pode fazer você pensar: “Cada clique do ​mouse tem o potencial de levar a uma violação de segurança”. ​Esse nível de escrutínio como profissional de segurança ​ajuda você a se preparar para ​o pior cenário, mesmo que isso não aconteça. ​Analistas iniciantes podem ajudar a proteger ativos de baixo nível, ​como a rede Wi-Fi convidada de uma organização, e ​ativos de alta importância, como propriedade intelectual, ​segredos comerciais, PII e até informações financeiras. ​Sua mentalidade de segurança permite que você ​proteja todos os níveis de ativos. ​No entanto, se um incidente ocorrer, ​isso não significa que você responda a ​todos os incidentes da mesma forma. ​Então, discutiremos a priorização de incidentes ​um pouco mais tarde no curso.\
​Ter uma forte mentalidade de segurança ​pode ajudar a diferenciá-lo de ​outros candidatos ao se ​preparar para ingressar na profissão de segurança. ​Pode até ser uma boa ideia fazer ​referência a essa fundação em futuras entrevistas de emprego. ​Discutiremos a preparação da entrevista ​em detalhes, posteriormente no curso. ​A seguir, vamos nos concentrar ​na detecção de incidentes com mais detalhes.

## Classificação de dados e recursosSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

É importante proteger as operações comerciais e os ativos de uma organização contra ameaças, riscos e vulnerabilidades de segurança. Você aprendeu anteriormente o que significa ter uma mentalidade de segurança. Essa mentalidade pode ajudá-lo a identificar e reduzir os riscos de segurança e os possíveis incidentes.

Nesta leitura, você aprenderá sobre os principais tipos de classificação de dados e a diferença entre os ativos de baixo e alto nível de uma organização.

### Classificação para segurança

Os profissionais de segurança classificam os tipos de dados para ajudá-los a proteger adequadamente uma organização contra ataques cibernéticos que afetam negativamente as operações comerciais. Veja a seguir uma análise dos tipos de dados mais comuns:

* **Dados públicos**
* **Dados privados**
* **Dados sensíveis**
* **Dados confidenciais**

#### Dados públicos

**Os dados públicos** já estão acessíveis ao público e representam um risco mínimo para a organização se forem visualizados ou compartilhados por outras pessoas. Embora esses dados estejam abertos ao público, eles ainda precisam ser protegidos contra ataques de segurança. É essencial implementar medidas básicas de segurança para protegê-los de possíveis ameaças. Exemplos de dados públicos incluem comunicados à imprensa, descrições de cargos e materiais de marketing.

#### Dados privados

Esse tipo de classificação de dados tem um nível de segurança mais alto. **Os dados privados** são informações que devem ser mantidas longe do público. Se um indivíduo obtiver acesso não autorizado a dados privados, esse evento poderá representar um sério risco para uma organização.

Exemplos de dados privados podem incluir endereços de e-mail da empresa, números de identificação de funcionários e dados de pesquisa de uma organização.

#### Dados confidenciais

Essas informações devem ser protegidas de todos que não tenham acesso autorizado. O acesso não autorizado a dados confidenciais pode causar danos significativos às finanças e à reputação de uma organização.

**Os dados confidenciais** incluem informações de identificação pessoal (PII), informações sensíveis de identificação pessoal (SPII) e informações de saúde protegidas (PHI). Exemplos desses tipos de dados confidenciais são números de contas bancárias, nomes de usuário e senhas, números de segurança de dados (que os cidadãos dos EUA usam para informar seus salários ao governo), senhas, números de passaporte e informações médicas.

#### Dados confidenciais

Esse tipo de classificação de dados é importante para as operações comerciais contínuas de uma organização.**Os dados confidenciais** geralmente têm limites quanto ao número de pessoas que têm acesso a eles. O acesso a dados confidenciais às vezes envolve a assinatura de contratos de confidencialidade (NDAs) - contratos legais que obrigam duas ou mais partes a proteger as informações - para proteger ainda mais a confidencialidade dos dados.

Exemplos de dados confidenciais incluem informações proprietárias, como segredos comerciais, registros financeiros e dados governamentais confidenciais.

### Classificação de ativos

**Classificação de ativos** significa rotular os ativos com base na sensibilidade e na importância para uma organização. A classificação dos ativos de uma organização varia de baixo a alto nível.

Os dados públicos são um ativo de baixo nível. Eles estão prontamente disponíveis para o público e não terão um impacto negativo em uma organização se forem comprometidos. Dados sensíveis e dados confidenciais são ativos de alto nível. Eles podem ter um impacto negativo significativo em uma organização se forem vazados publicamente. Esse impacto negativo pode levar à perda da vantagem competitiva, da reputação e da confiança dos clientes de uma empresa. O endereço do site de uma empresa é um exemplo de ativo de baixo nível. Um e-mail interno dessa empresa discutindo segredos comerciais é um exemplo de um ativo de alto nível.

### Principais conclusões

Toda empresa tem sua própria política de classificação de dados que identifica que tipo de dados está em cada categoria. Será importante para seu sucesso como profissional de segurança familiarizar-se com essa política. É importante compreender os diferentes tipos de classificação de dados e ativos. Isso o ajuda a priorizar quais dados precisam ser mais protegidos. Também o ajuda a reconhecer quais ativos precisam de níveis mais altos de segurança e quais ativos precisam de segurança mínima.

## Recuperação de desastres e continuidade dos negóciosSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

A função de um profissional de segurança é garantir que os dados e recursos de uma empresa estejam protegidos contra ameaças, riscos e vulnerabilidades. No entanto, às vezes as coisas não saem como planejado. Há ocasiões em que ocorrem incidentes de segurança. Você já aprendeu que as violações de segurança podem levar a consequências financeiras e à perda de credibilidade junto aos Clientes ou a outras empresas do setor.

Esta leitura discutirá a necessidade de criar planos de continuidade dos negócios e de recuperação de desastres para minimizar o impacto de um incidente de segurança nas operações comerciais de uma organização. Os analistas precisam considerar a sequência de etapas a serem executadas pela equipe de segurança antes da implementação dos planos de continuidade dos negócios e de recuperação de desastres.

### Identificar e proteger

A criação de planos de continuidade dos negócios e de recuperação de desastres é a etapa final de um processamento de quatro partes pelo qual a maioria das equipes de segurança passa para ajudar a garantir a segurança de uma organização.

Primeiro, a equipe de segurança identifica os recursos que devem ser protegidos na organização. Em seguida, determina quais ameaças em potencial poderiam afetar negativamente esses recursos. Depois que as ameaças são determinadas, a equipe de segurança implementa ferramentas e processos para detectar possíveis ameaças aos recursos. Por fim, a TI ou a função comercial apropriada cria os planos de continuidade dos negócios e de recuperação de desastres. Esses planos são criados em conjunto. Os planos ajudam a minimizar o impacto de um incidente de segurança envolvendo um dos recursos da organização.

### Plano de continuidade dos negócios

O impacto de ataques de segurança bem-sucedidos em uma organização pode ser significativo. A perda de lucros e de clientes são dois resultados possíveis que as organizações nunca querem que aconteçam. Um **plano de continuidade** dos negócios é um documento que descreve os procedimentos para manter as operações comerciais durante e após uma interrupção significativa. Ele é criado juntamente com um plano de recuperação de desastres para minimizar os danos de um ataque bem-sucedido à segurança. Aqui estão quatro etapas essenciais para os planos de continuidade dos negócios:

* **Realizar uma análise do impacto nos negócios.** A etapa de análise do impacto nos negócios concentra-se nos possíveis efeitos que uma interrupção das funções de negócios pode ter em uma organização.
* **Identifique, documente e implemente as etapas para recuperar funções e processos críticos dos negócios.** Essa etapa ajuda a equipe de continuidade dos negócios a criar medidas acionáveis para responder a um evento de segurança.
* **Organize uma equipe de continuidade de negócios.** Esta etapa reúne vários membros da organização para ajudar a executar o plano de continuidade de negócios, caso seja necessário. Os membros da equipe geralmente pertencem aos departamentos de segurança cibernética, TI, RH, Comunicação e Operações.
* **Realize um Treinamento para a equipe de continuidade** de negócios. A equipe considera diferentes cenários de Risco e se prepara para ameaças à segurança durante esses exercícios de treinamento.

### Plano de recuperação de desastres

Um **plano de recuperação de desastres** permite que a equipe de segurança de uma organização defina as etapas necessárias para minimizar o impacto de um incidente de segurança, como um ataque bem-sucedido de ransomware que impediu a equipe de produção de recuperar determinados dados. Ele também ajuda a equipe de segurança a resolver a ameaça à segurança. Um plano de recuperação de desastres geralmente é criado juntamente com um plano de continuidade de negócios. As etapas para criar um plano de recuperação de desastres devem incluir:

* Implementação de estratégias de recuperação para restaurar o software
* Implementação de estratégias de recuperação para restaurar a funcionalidade do hardware
* Identificação de aplicativos e dados que possam ser afetados após a ocorrência de um incidente de segurança

### Principais conclusões

Os planos de recuperação de desastres e de continuidade de negócios são importantes para a postura de segurança de uma organização. É essencial que a equipe de segurança tenha planos para manter as operações de negócios da organização em andamento, caso ocorra um incidente de segurança.

## Encaminhamento com um propósitoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Você aprendeu anteriormente sobre o encaminhamento de incidentes de segurança e as habilidades necessárias para ajudá-lo a encaminhar incidentes. Nesta leitura, você aprenderá a importância de encaminhar problemas de segurança e o possível impacto de não encaminhar um problema.

### Encaminhamento de incidentes

O encaminhamento de incidentes de segurança é o processamento da identificação de um possível incidente de segurança. Durante esse processamento, os possíveis incidentes são transferidos para um departamento ou membro da equipe mais experiente. AS Como analista de segurança, espera-se que você reconheça possíveis problemas, como quando um funcionário insere excessivamente as credenciais erradas em sua conta, e informe o fato à pessoa apropriada. ### Notificação de violações

Muitos países têm leis de notificação de violações, portanto, é importante familiarizar-se com as leis aplicáveis na área em que sua empresa está operando. As leis de notificação de violações exigem que as empresas e entidades governamentais notifiquem as pessoas sobre violações de segurança que envolvam informações de identificação pessoal (PII). As PII incluem números de identificação pessoal (por exemplo, números de Seguro Social, números de carteira de motorista, etc.), registros médicos, endereços e outras informações confidenciais de clientes. AS Como analista de segurança iniciante, você precisará estar ciente das várias leis de segurança, especialmente porque elas são atualizadas regularmente.

### Problemas de segurança de baixo nível

Riscos de segurança de baixo nível são riscos de segurança que não resultam na exposição ao risco de PII. Esses problemas podem incluir os seguintes riscos e outros:

* Um funcionário com uma tentativa de login com falha em sua conta
* Um funcionário que faz download de um software não aprovado em seu laptop de trabalho

Esses problemas não são desafios de segurança significativos, mas devem ser investigados mais a fundo caso precisem ser encaminhados. Um funcionário que digita uma senha duas ou três vezes pode não ser motivo de preocupação. Mas se esse funcionário digitar uma senha 15 vezes em 30 minutos, pode haver um problema que precise ser encaminhado. E se as várias tentativas de login fracassadas forem uma tentativa de um agente mal-intencionado de comprometer a conta de um funcionário? E se um funcionário baixar um jogo da Internet ou um software em seu laptop de trabalho que esteja infectado com malware? Você aprendeu anteriormente que o malware é um software projetado para danificar dispositivos ou redes de computadores. Se for feito o download de um malware na rede de uma organização, isso pode levar a perdas financeiras e até mesmo à perda de reputação com os Clientes da organização. Embora os problemas de segurança de baixo nível não sejam considerados ameaças significativas à segurança, eles ainda devem ser investigados para garantir que resultem em um impacto mínimo para a organização.

### O processamento de encaminhamento

Toda empresa tem protocolos e procedimentos diferentes, inclusive políticas de encaminhamento exclusivas. Essas políticas detalham quem deve ser notificado quando um alerta de segurança é recebido e quem deve ser contatado se o primeiro a responder não estiver disponível. A política também determinará como alguém deve encaminhar especificamente um incidente, seja por meio da mesa de TI, de uma ferramenta de gerenciamento de incidentes ou da comunicação direta entre os membros da equipe de segurança.

### Principais conclusões

O encaminhamento de incidentes é essencial para proteger os dados de uma organização. Cada organização pode ter uma maneira diferente de encaminhar incidentes de segurança. Um analista de segurança deve estar ciente dos protocolos de encaminhamento que estão em vigor em sua organização. Tanto os problemas de segurança pequenos quanto os grandes devem ser encaminhados à equipe ou aos membros da equipe apropriados.

## Reconhecer as funções e responsabilidades durante o EncaminhamentoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Você aprendeu anteriormente sobre vários tipos de classificação de incidentes e como esses incidentes podem impactar uma organização.

Esta leitura discutirá as Funções dos vários Membros da equipe que fazem parte do processamento do Encaminhamento de Incidentes. Lembre-se de que nem todas as organizações são iguais, e algumas funções e responsabilidades podem ser identificadas usando diferentes terminologias e definições.

### Proprietários dos dados

Um proprietário de dados é a pessoa que decide quem pode acessar, editar, usar ou destruir suas informações. Os proprietários de dados têm controle administrativo sobre hardware ou software de informações específicas e são responsáveis pela classificação, proteção, acesso e uso dos dados da empresa. Por exemplo, considere uma situação em que um funcionário obtém acesso não autorizado a um software que não precisa usar para o trabalho. Esse tipo de evento de segurança seria encaminhado ao proprietário dos dados desse software.

### Controladores de dados

Os controladores de dados determinam o procedimento e a finalidade do processamento de dados. Essa função se concentra principalmente na coleta de informações pessoais dos Clientes. O controlador de dados determina como esses dados serão usados. O controlador de dados também garante que os dados sejam usados, armazenados e processados de acordo com os regulamentos relevantes de Segurança e Privacidade dos dados. Se as informações confidenciais dos clientes estivessem em risco, esse evento seria encaminhado aos controladores de dados.

### Processadores de dados

Os processadores de dados se reportam diretamente ao controlador de dados e são responsáveis pelo processamento dos dados em nome do controlador de dados. Em geral, o processador de dados é um fornecedor e muitas vezes é encarregado de instalar medidas de Segurança de Dados para ajudar a proteger os dados. Os Problemas de processamento de dados são normalmente encaminhados ao indivíduo que supervisiona a organização terceirizada responsável pelo processamento de dados.

### Custódios de dados

Os custodiantes de dados atribuem e removem o acesso a software ou hardware. Os custodiantes são responsáveis pela implementação de controles de segurança dos dados pelos quais são responsáveis, pela concessão e revogação de acesso a esses dados, pela criação de políticas relativas à forma como esses dados são armazenados e transmitidos, pelo aconselhamento sobre possíveis ameaças a esses dados e pelo monitoramento dos dados. Os guardiões dos dados são notificados quando os controles de segurança de dados precisam ser reforçados ou foram comprometidos.

### Diretores de proteção de dados (DPOs)

Os encarregados da proteção de dados são responsáveis por monitorar a conformidade interna dos procedimentos de proteção de dados de uma organização. Esses indivíduos aconselham a equipe de Segurança de dados sobre as obrigações exigidas pelos padrões e procedimentos de proteção de dados da organização. Eles também realizam avaliações para determinar se as medidas de segurança em vigor estão ou não protegendo adequadamente os dados, conforme necessário. Os DPOs são notificados quando os padrões ou protocolos estabelecidos são violados.

### Principais lições

O encaminhamento de incidentes exige que vários membros da equipe de segurança atuem como um só. Os analistas iniciantes devem estar familiarizados com as funções e responsabilidades dos diferentes Membros da equipe de segurança. AS, como analista de nível básico, normalmente encaminhará os incidentes ao seu supervisor direto. Entretanto, ainda é importante conhecer os diferentes Membros da equipe à medida que avança em sua carreira de segurança, pois isso o ajudará a reconhecer quais incidentes devem ser relatados a quem.

​Falamos um pouco sobre a importância de sua função quando se trata da ​escalada de incidentes. ​Até discutimos alguns tipos de incidentes que você pode encontrar. ​Mas quais são as medidas reais que você precisa tomar para escalar adequadamente um incidente? ​A resposta a essa pergunta, na verdade, depende da organização ​para a qual você trabalha. ​Não há um padrão ou processo definido para o ​escalonamento de incidentes que todas as organizações usem. ​Cada equipe de segurança tem seus próprios processos e ​procedimentos quando se trata de lidar com incidentes. ​Neste vídeo, discutiremos as diretrizes gerais para a ​escalação de incidentes e como aplicá-las no trabalho.\

* **Acesso não autorizado:** Acessível: ocorre quando um indivíduo obtém acesso digital ou físico a um sistema, dados ou aplicativo sem permissão

Lesson 2 -

## O propósito e o impacto das partes interessadasSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Você aprendeu anteriormente sobre o Encaminhamento de Incidentes e os vários tipos de classificação de incidentes de segurança. Você também aprendeu sobre o impacto que esses incidentes podem ter sobre as operações comerciais de uma organização.

Esta leitura explorará os indivíduos que têm um interesse significativo nessas operações comerciais: as partes interessadas.

### Quem são as partes interessadas?

Uma **parte interessada** é definida como um indivíduo ou grupo que tem interesse em qualquer decisão ou atividade de uma organização. Uma grande parte do que você fará como analista de segurança é relatar suas descobertas a várias partes interessadas em segurança.

### Níveis de partes interessadas

Há muitos níveis de partes interessadas nas grandes organizações. Como analista de nível básico, talvez você só se comunique diretamente com alguns deles. Embora talvez você não se comunique com todas as partes interessadas em segurança de uma organização, é importante entender quem são as principais partes interessadas:

* Um gerente de riscos de segurança cibernética é um profissional responsável por liderar os esforços para identificar, avaliar e reduzir os riscos de segurança em uma organização.
* O CEO (Chief Executive Officer), também conhecido como diretor executivo, é a pessoa de mais alto escalão em uma organização. É improvável que você se comunique diretamente com essa parte interessada como analista de nível básico.
* Um diretor financeiro, também conhecido como CFO, é outra parte interessada de alto nível com a qual é improvável que você se comunique diretamente.
* Um diretor de segurança das informações, também conhecido como CISO, é a parte interessada de mais alto nível em segurança. Também é improvável que você se comunique diretamente com essa parte interessada como analista de nível básico.
* Um gerente de operações supervisiona as operações de segurança cotidianas. Esses indivíduos lideram Equipes relacionadas ao desenvolvimento e à implementação de estratégias de segurança que protegem uma organização contra ameaças cibernéticas.

Os CFOs e CISOs concentram-se no panorama geral, como o possível ônus financeiro de um incidente de segurança, enquanto outras funções, como os gerentes de operações, concentram-se mais no impacto sobre as operações diárias. Embora você raramente interaja diretamente com as partes interessadas em segurança de alto nível, ainda assim é importante reconhecer sua relevância.

### Comunicação com partes interessadas para analistas de nível básico

Dois exemplos de partes interessadas em segurança com as quais você pode se comunicar regularmente são os gerentes de operações e os gerentes de riscos. Ao se reportar a essas partes interessadas, você precisará comunicar claramente o problema de segurança atual e suas possíveis causas. Em seguida, os gerentes de operações determinarão as próximas etapas e coordenarão outros membros da equipe para remediar ou resolver o problema.

Por exemplo, você pode relatar várias tentativas de login fracassadas de um funcionário ao seu gerente de operações. Essa parte interessada pode entrar em contato com o supervisor do funcionário para garantir que a ocorrência seja um problema genuíno de digitação da senha errada ou para determinar se a conta foi comprometida. A parte interessada e o supervisor talvez também precisem discutir as consequências para as operações cotidianas se as tentativas genuínas de login falho puderem levar a bloqueios de contas que possam afetar as operações comerciais. Como analista de segurança de nível básico, você pode desempenhar uma função na implementação de medidas preventivas, uma vez que as próximas etapas tenham sido determinadas.

### De uma parte interessada para a outra

Os gerentes de operações e os gerentes de riscos são partes interessadas que dependem dos analistas de nível básico e de outros Membros da equipe para mantê-los informados sobre os eventos de segurança nas operações diárias. Essas partes interessadas geralmente se reportam aos CISOs e CFOs para fornecer uma Narrativa mais ampla do quadro geral de segurança da organização. Embora você não se comunique regularmente com as partes interessadas de alto nível, é importante reconhecer que seus esforços ainda atingem os níveis mais altos das partes interessadas em segurança da organização. Esses outros membros da equipe mantêm as partes interessadas de alto nível informadas sobre as medidas e os protocolos de segurança em vigor que ajudam continuamente a proteger a organização.

### Principais conclusões

As partes interessadas desempenham um papel importante na garantia da segurança de uma organização. Os analistas iniciantes devem ter uma compreensão básica dos diferentes níveis de partes interessadas na segurança de uma organização. Os analistas iniciantes não se comunicarão com todas as partes interessadas em segurança de uma empresa, mas há certas partes interessadas às quais o analista precisará fornecer atualizações. Essas atualizações acabarão sendo relatadas às partes interessadas de nível mais sênior, como o CISO e o CFO.

## Comunicar-se efetivamente com as partes interessadasSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Você aprendeu anteriormente sobre as partes interessadas em segurança e sua importância em uma organização. ### Vá direto ao ponto

As partes interessadas em segurança têm funções e responsabilidades que são sensíveis ao tempo e impactam os negócios. É importante que as comunicações que eles recebem e as ações que precisam tomar sejam claras. Para ir direto ao ponto em suas comunicações, pergunte-se:

* Por que é importante que ela saiba?
* Quando ela precisa agir?
* Como posso explicar a situação de uma maneira não técnica?

### Seguir os protocolos

Ao entrar pela primeira vez em uma equipe de segurança, você deverá conhecer os diferentes protocolos e procedimentos em vigor para se comunicar com as partes interessadas e outros membros da organização. É importante certificar-se de que sabe quais aplicativos e formas de comunicação são aceitáveis antes de começar a se comunicar com as partes interessadas, como reuniões presenciais, videoconferências, e-mails ou aplicativos de bate-papo da empresa.

### Comunique-se com impacto

Você aprendeu anteriormente sobre as diferentes partes interessadas de uma organização e em quais áreas específicas elas se concentram. No início de sua carreira no campo da segurança cibernética, é mais provável que interaja com partes interessadas de baixo nível, como gerentes de operações ou Gerentes de riscos de segurança, que estão interessados nas operações diárias, como geração de registros. As partes interessadas de nível sênior podem estar mais interessadas nos riscos subjacentes, como o possível ônus financeiro de um incidente de segurança - em oposição aos detalhes sobre a geração de registros.

Ao se comunicar com um gerente de operações, certifique-se de abordar informações relevantes relacionadas às suas responsabilidades diárias, como anomalias nos registros de dados que você está encaminhando. ## Use a IA generativa para trabalhar de forma mais inteligente e rápidaSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Na leitura introdutória, você aprendeu que IA se refere a programas de computadores que podem realizar tarefas cognitivas normalmente associadas à inteligência humana. Um tipo específico de IA é a **IA generativa** (gen IA), que é a IA que pode gerar novos conteúdos, como texto, imagens ou outras mídias. [Gemini](http://gemini.google.com/), [ChatGPT](https://chat.openai.com/) da OpenAI e[ Microsoft Copilot](https://www.microsoft.com/en-us/microsoft-copilot/) são exemplos de ferramentas de IA generativa. Você pode interagir com uma ferramenta de IA generativa inserindo um **prompt**, que é uma entrada que fornece instruções a uma ferramenta de IA sobre como gerar resultados. Em seguida, a ferramenta cria um novo conteúdo com base nesse prompt.

Em seu trabalho como profissional de segurança cibernética, você pode aproveitar as ferramentas de IA generativa para ajudá-lo a concluir tarefas práticas e criativas. Considere estas aplicações de ferramentas de IA generativa que podem ajudá-lo a trabalhar com mais eficiência e eficácia:

* **Criar conteúdo**. Você pode usar ferramentas de IA generativa para gerar texto, imagens e outras mídias. Por exemplo, você pode criar um grande conjunto de dados falsos para testar as ferramentas de segurança cibernética que sua organização usa.
* **Analisar informações rapidamente**. As ferramentas de IA generativa podem analisar grandes quantidades de conteúdo rapidamente. Por exemplo, você pode usar a IA generativa para resumir relatórios ou transcrições de reuniões que contenham informações importantes relacionadas à segurança da sua organização, ajudando a identificar os principais detalhes mais rapidamente.
* **Responda a perguntas de forma detalhada e com nuances**. A IA generativa é eficaz em resumir informações, o que a torna útil para pesquisas. Por exemplo, você pode solicitar a uma ferramenta de IA generativa que forneça informações sobre tipos comuns de ameaças à segurança cibernética, como malware e ransomware.

### O que são entrevistas técnicas?

Depois de se candidatar a um emprego em segurança cibernética e receber o interesse de um recrutador, você poderá ser convidado para uma entrevista introdutória, uma segunda entrevista com um gerente de contratação e um painel de entrevistas. A principal diferença entre as entrevistas técnicas e outras entrevistas é o foco no conhecimento necessário de ferramentas específicas.

### Python

Python é uma linguagem de programação que serve como uma ferramenta importante em segurança, e você poderá ser questionado sobre ela durante uma entrevista técnica. ### Técnicas gerais

Durante a entrevista técnica, talvez você deva demonstrar conhecimento básico de vários conceitos gerais de segurança. Por exemplo, talvez seja necessário demonstrar familiaridade com **estruturas de segurança**, que são diretrizes usadas para criar planos que ajudem a reduzir riscos e ameaças à Segurança de dados e à Privacidade dos dados. Ao discutir as estruturas de segurança, seria útil mencionar seu conhecimento de estruturas específicas do NIST, como a Estrutura de Segurança Cibernética (CSF). Outro conceito técnico que você pode discutir durante uma entrevista técnica é a segurança de rede. Talvez você se lembre de que **a segurança de rede** é a prática de manter a infraestrutura de rede de uma organização protegida contra acesso não autorizado. Revisar os diferentes conceitos técnicos que você aprendeu ao longo deste programa é uma boa maneira de se preparar para uma entrevista técnica. ### Possíveis perguntas para entrevistas técnicas

Cada entrevista técnica será diferente, dependendo da empresa e dos entrevistadores. Mas aqui estão algumas possíveis perguntas de entrevistas técnicas para ajudá-lo a se preparar:

* O que é o modelo TCP/IP?

O modelo TCP/IP é uma estrutura usada para visualizar como os dados são organizados e transmitidos em uma rede.

* O que é o modelo OSI?

O modelo OSI significa modelo de interconexão de sistemas abertos (OSI). É um conceito padronizado que descreve as sete camadas que os computadores usam para se comunicar e enviar dados pela rede.

* O que são ferramentas SIEM e para que são usadas?

As ferramentas SIEM são ferramentas de gerenciamento de eventos e informações de segurança usadas por profissionais de segurança para identificar e analisar ameaças, riscos e vulnerabilidades de segurança.
