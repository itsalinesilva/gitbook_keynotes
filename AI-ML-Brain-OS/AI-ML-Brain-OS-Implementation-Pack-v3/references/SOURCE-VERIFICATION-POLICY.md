# Política de verificação de fontes

## Níveis de evidência
- **A — Primária/autoritativa**: especificação, documentação oficial, paper original, dataset primário, regulador, repositório original.
- **B — Secundária rigorosa**: revisão sistemática, veículo técnico com método e autoria claros, análise com fontes verificáveis.
- **C — Sinal exploratório**: postagem, newsletter, comentário, fórum ou material comercial.
- **D — Não verificada**: origem, data, autoria ou integridade não confirmadas.

## Regras de uso
- Claims críticos devem priorizar A; B pode contextualizar; C serve para gerar hipóteses, não confirmar sozinho.
- Verificar data de publicação e data da última atualização separadamente.
- Registrar data de acesso e versão consultada.
- Buscar confirmação independente para afirmações relevantes; republicações da mesma origem não contam como confirmação independente.
- Distinguir “fonte oficial” de “fonte independente”: oficial é primária para a posição do emissor, não necessariamente neutra.
- Registrar contraevidência, limitações, conflito de interesse e escopo.
- Usar snapshots/hash quando conteúdo puder mudar, respeitando direitos e políticas de acesso.
- Não usar uma pontuação agregada de reputação como substituto de julgamento contextual.
- Definir prazos de revisão por volatilidade: alta para preços, APIs, segurança e notícias; menor para fundamentos estáveis.
