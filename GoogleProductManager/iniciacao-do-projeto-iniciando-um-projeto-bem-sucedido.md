### Lesson 2 - Por que o Início do Projeto é essencial?

​Bem-vindo de volta! No último curso, você aprendeu que a iniciação é a primeira fase do ​ciclo de vida do projeto, seguida pelo planejamento, ​execução e encerramento. Faz sentido, certo? ​Independentemente da metodologia escolhida, todos os projetos precisam começar em algum lugar. ​Vamos falar mais sobre a iniciação e por que ela é importante para ​o sucesso de um projeto. ​Como a iniciação é a primeira fase do projeto, ​é muito importante acertar. ​Uma iniciação bem planejada resulta em uma base sólida para seu projeto e o ​prepara para o sucesso.\
​Início: A iniciação começa após a ​identificação de um problema ou oportunidade dentro de uma organização. ​Freqüentemente, partes interessadas, como líderes seniores de uma empresa, ​iniciam um projeto para atender a uma necessidade específica da empresa. ​Por exemplo, talvez a empresa queira lançar um novo produto, ​melhorar o bem-estar dos funcionários ou reduzir custos em um determinado departamento. ​É sua responsabilidade como gerente de projeto ajudar a identificar as metas, os ​recursos e outros detalhes do projeto com base nas discussões iniciais com as ​partes interessadas do projeto. Mesmo que outra pessoa tenha uma ideia para ​o projeto, ainda é seu trabalho descobrir todas as peças importantes que precisam ser ​reunidas para realizar o trabalho. ​A fase de iniciação é um momento crucial para fazer as perguntas certas às partes interessadas, ​realizar pesquisas, determinar recursos e ​documentar claramente os principais componentes de um projeto. ​Isso ajudará você a solidificar o escopo ou o limite do projeto.\
​Se isso parecer um pouco difícil, não se preocupe. ​Falaremos mais sobre o escopo do projeto posteriormente ​neste curso. Se o projeto não for iniciado corretamente, ​as coisas podem dar errado muito rápido. ​Por exemplo, sem uma compreensão suficiente das metas do projeto, ​você pode subestimar quais recursos você precisa ou quanto tempo o projeto pode levar. Ou, sem concordar com as partes interessadas sobre o que significa sucesso, ​você pode pensar que o projeto foi concluído com sucesso, ​enquanto as partes interessadas podem pensar que ele não atingiu suas metas. ​Ficar na mesma página e obter clareza durante a fase ​de iniciação pode economizar muito tempo e trabalho extra para todos durante todo o projeto. ​O início adequado também ajuda a garantir que os benefícios dos ​resultados do projeto superem os custos do projeto.\
​Para determinar isso, você fará o que é chamado de análise de custo-benefício, ​que é o processo de somar o valor esperado de um projeto ​(os benefícios) e compará-lo aos custos em dólares. ​Para fazer isso, você trabalhará com as partes interessadas para considerar algumas questões. ​Para determinar os benefícios de um projeto, ​essas perguntas podem incluir: ​Que valor esse projeto criará? ​Quanto dinheiro esse projeto poderia salvar nossa organização? ​Quanto dinheiro isso trará dos clientes existentes? ​Quanto tempo será economizado? ​Como a experiência do usuário será aprimorada? E para determinar os custos do projeto, ​essas perguntas podem incluir: ​Quanto tempo as pessoas terão que gastar nesse projeto?\
​Quais serão os custos únicos? ​Há algum custo contínuo? ​E quanto aos custos de longo prazo? ​Os benefícios de um projeto devem sempre superar os custos, ​por isso é muito importante que você considere essas questões desde o início. ​A seguir, falaremos mais sobre a fase de iniciação e ​exploraremos os principais componentes do início de um projeto. ​Tchau por enquanto!

### Lesson 3 - Componentes-chave do Início do Projeto

​Olá e bem-vindo de volta. ​Você acabou de aprender sobre a fase de iniciação do ciclo de vida do projeto e ​por que é tão importante acertá-la. ​Em seguida, ensinarei sobre os principais componentes que compõem a iniciação e ​como essas peças levam à fase de planejamento de um projeto. ​Há vários componentes chave da iniciação que você precisa ​considerar para que seu projeto seja bem-sucedido: metas, escopo, ​resultados, critérios de sucesso, partes interessadas e recursos. ​Primeiro, você precisa considerar as metas do projeto, ​a meta é o que você foi convidado a fazer e o que está tentando alcançar. ​Todos os projetos devem ter metas claras e, ​muitas vezes, elas serão determinadas pelos líderes seniores da empresa, com a sua ajuda. ​A partir daí, você começará a considerar o escopo do projeto.\
​Esse é o processo para definir o trabalho que precisa acontecer para concluir ​o projeto. ​Você também precisa pensar nos resultados do projeto. ​Eles são os produtos e serviços que você criará para seu cliente, cliente ou ​patrocinador do projeto. ​Os resultados podem ser qualquer coisa, desde recursos e ​funcionalidades do produto até documentação, processos e muito mais, ​qualquer coisa que permita que a meta do seu projeto seja alcançada. ​Os resultados são enviados para ajudar você a atingir as metas do seu projeto. ​Além disso, é importante ter em mente que as entregas podem ser tangíveis ou intangíveis. Um exemplo de entrega tangível pode ser o ​envio de um capítulo de um manuscrito.\
​Se o objetivo é publicar um livro didático. Ou se a meta do seu projeto ​for concluir a implementação de um novo software de ponto de venda em uma loja de varejo, ​agendar sessões de treinamento da equipe pode ser um resultado intangível. ​Depois que as metas, o escopo e os resultados forem determinados, ​você precisará considerar os critérios de sucesso. Critérios de sucesso são os padrões pelos ​quais você mede o sucesso de um projeto em atingir suas metas. ​Outra consideração importante são suas partes interessadas. ​As partes interessadas são fundamentais para tomar decisões informadas em cada etapa do projeto, ​incluindo a fase de iniciação. ​Eles são as pessoas que têm interesse e ​são afetadas pela conclusão e pelo sucesso de um projeto.\
​Como resultado, eles geralmente são fundamentais para determinar as metas, os ​objetivos, as entregas e os critérios de sucesso do projeto, desde a criação da ​ideia até o delineamento das expectativas de seus resultados. ​À medida que você avança na fase de iniciação, é seu trabalho garantir que ​você entenda as necessidades das partes interessadas do projeto desde o início. ​Também é sua função garantir que todas as partes interessadas concordem com as metas ​e a missão geral do projeto antes de passar para a próxima fase. ​Agora, vamos falar sobre recursos, os recursos geralmente se referem ao orçamento ​, pessoas, materiais e outros itens que você terá à sua disposição. ​É muito importante pensar cuidadosamente sobre essas peças desde o início. ​Ninguém quer começar um projeto, ​apenas para perceber, no meio do caminho, que não tem dinheiro ou ​pessoas suficientes para concluir o trabalho. Isso seria uma bagunça.\
​Finalmente, depois de estabelecer suas metas, escopo, ​resultados, critérios de sucesso, partes interessadas e recursos, ​é hora de criar um plano de projeto. ​Um contrato de projeto é um documento que contém todos os detalhes do projeto. ​Os estatutos do projeto definem claramente o projeto e suas metas e ​descrevem o que é necessário para realizá-los. ​Uma carta de projeto permite que você se organize, configure um framework para ​o que precisa ser feito e comunique esses detalhes a outras pessoas. ​Depois de redigir o regulamento, você revisaria o documento com as principais partes ​interessadas para obter sua aprovação para entrar na fase de planejamento. ​A seguir, você aprenderá mais sobre os estatutos de projetos e ​até terá a chance de criar um você mesmo. ​Espero que você esteja começando a ver como os principais componentes da iniciação ​ajudam a estabelecer a base de um projeto sólido.\
​Para recapitular rapidamente, você coleta informações sobre suas metas, escopo, ​resultados, critérios de sucesso, partes interessadas e ​recursos e documenta essas informações no regulamento do projeto. ​Durante o restante deste curso, ​falaremos mais sobre cada um dos componentes descritos até agora. ​Você chegou tão longe e aprendeu muito, continue com o excelente trabalho.

Anteriormente, você aprendeu que uma **Análise de custo-benefício** é o processamento da soma do valor esperado de um projeto - os Benefícios - e sua comparação com os custos em dólares. Nesta leitura, discutiremos os benefícios da realização de uma Análise de custo-benefício, as perguntas orientadoras para ajudar você e as partes interessadas a realizá-la e como calcular o Retorno sobre o investimento (ROI).

### **Benefícios de uma análise de custo-benefício**

Uma Análise de custo-benefício pode minimizar os Riscos e maximizar os Benefícios para projetos e organizações. Ela pode ajudá-lo a se comunicar claramente com as partes interessadas e os executivos e a manter seu projeto no caminho certo. Como esse tipo de análise usa dados objetivos, pode ajudar a reduzir os viéses e impedir que os interesses próprios das partes interessadas influenciem as decisões.

A comparação dos Benefícios de um projeto com seus Custos pode ajudá-lo a apresentar um caso de negócios sólido às partes interessadas e à liderança e garantir que sua organização busque os projetos mais lucrativos ou úteis. As organizações usam a Análise de custo-benefício para reduzir o desperdício e investir seus recursos de forma responsável.

### **Perguntas orientadoras para uma Análise de custo-benefício**

Quando se busca um projeto, os Benefícios devem superar os Custos. É importante que você e as partes interessadas considerem perguntas como as que seguem logo no início, enquanto você prepara a proposta.

Para determinar os Benefícios de um projeto, você pode perguntar:

* Que valor esse projeto criará?
* Quanto dinheiro esse projeto poderia economizar para nossa organização?
* Quanto dinheiro ele trará dos clientes existentes?
* Quanto tempo será economizado?
* Como ele melhorará a experiência do cliente?

E para determinar os Custos de um projeto, considere questões como:

* Quanto tempo as pessoas terão de dedicar a esse projeto?
* Quais são os custos únicos?
* Há algum custo contínuo?
* E quanto aos custos de longo prazo?

Você também pode considerar perguntas sobre **Benefícios intangíveis**. Esses são ganhos que não são quantificáveis, como, por exemplo:

* **Satisfação dos clientes**. O projeto aumentará a retenção de clientes, fazendo com que eles gastem mais com os produtos ou serviços da empresa?
* Satisfação**dos funcionários**. É provável que o projeto melhore o moral dos funcionários, reduzindo a rotatividade?
* **Produção dos funcionários**. O projeto reduzirá as horas extras dos funcionários, economizando dinheiro para a empresa?
* **Percepção da marca**. É provável que o projeto melhore a percepção e o reconhecimento da marca da empresa, atraindo mais Clientes ou proporcionando uma vantagem competitiva?

Você também pode inverter essas perguntas para considera&#x72;_**os Custos**_ **intangíveis** . Esses são custos que não são quantificáveis. Por exemplo, o projeto pode colocar em risco a retenção de clientes, a satisfação dos funcionários ou a percepção da marca?

Ao atribuir valores a custos e benefícios tangíveis ou intangíveis, você pode fazer referência a projetos anteriores semelhantes, realizar pesquisas do setor ou consultar especialistas.

### **Cálculo de custos e benefícios**

O processamento do cálculo de custos e benefícios também é chamado de cálculo do **Retorno sobre o investimento**( **ROI**). Há muitas maneiras de determinar o ROI de um projeto, mas a maneira mais fácil é comparar os custos iniciais e contínuos com seus Benefícios ao longo do tempo.

Uma fórmula comum de ROI é:

<figure><img src="https://d3c33hcgiwev3.cloudfront.net/imageAssetProxy.v1/5WgkcOwJRaqoJHDsCRWqcg_17254e77f84d45a89ab513f21eef88d9_ROI-formula.png?expiry=1780263568197&#x26;hmac=t-A30FjKhm2DmkiLju13fAw8-21naEN3PnH4TwCEQV4" alt=""><figcaption></figcaption></figure>

Nessa fórmula, **G** representa os ganhos financeiros que você espera do projeto e **C#** representa os custos iniciais e contínuos do seu investimento no projeto.

Por exemplo, imagine que seu projeto custe US$ 6.000 no início mais US$ 25 por mês durante 12 meses. Vinte e cinco dólares por 12 meses equivalem a US$ 300 por ano, o que significa que seu custo total é de US$ 6.300. Você estima que o projeto trará uma receita de US$ 10.000 ao longo desse ano. Isso lhe deixa com:

* G = $10,000
* C = $6,300

Agora, usando a Fórmula acima, você insere os valores da seguinte forma:

* (US$ 10.000 - US$ 6.300) ÷ US$ 6.300 = ROI

Em seguida, você prossegue com o cálculo:

* Primeiro, dentro dos parênteses: 10,000 - 6,300 = $3,700
* Em seguida, US$ 3.700 ÷ US$ 6.300 = 0,5873
* Finalmente, 0,5873 x 100 = 58,7%

O ROI é de 0,587, ou 58,7%. Como um ROI forte tende a ser qualquer coisa acima de 10%, você acha que 58,7% é um ROI forte e, portanto, decide prosseguir com o projeto.

### **Principais conclusões**

Ao realizar análises de custo-benefício para seus projetos em potencial, você pode usar como referência as perguntas orientadoras e a fórmula de ROI fornecidas nesta leitura.

### Lesson 7 -Como definir metas SMART

​Bem-vindo de volta, agora você sabe que ​as metas são importantes para o sucesso do seu projeto ​e sabe que elas precisam ser bem definidas ​para ajudar a manter seu projeto em andamento. ​Como seus resultados dependem de suas metas, ​é de seu interesse definir ​essas metas da forma mais bem definida possível. ​Para sua sorte, eu tenho ​um método fácil para fazer exatamente isso: ​definir Metas SMART. ​Eu já mencionei que as metas ​devem ser específicas e mensuráveis. ​O método SMART para avaliar metas ​adiciona mais três considerações para o sucesso. ​Seja alcançável, seja relevante e tenha um prazo limitado. ​Coloque-os todos juntos ​e o que você tem? Metas SMART.\
​Como gerente de projeto iniciante, ​você pode ou não definir as principais metas do projeto, ​mas precisará ​identificá-las e esclarecê-las conforme necessário, ​e é aí que o método SMART pode ser uma ferramenta valiosa. ​Vamos examinar mais de perto cada termo. ​Como já mencionei, ​se sua meta não for específica, ​você terá dificuldade em ​descobrir quanto tempo deve levar para ser ​concluída e se a alcançou ou não. ​Por exemplo, se a meta é ​simplesmente melhorar o tempo de resposta do atendimento ao cliente, ​isso não é muito específico. ​Diz o que você deseja alcançar em geral, ​mas não diz mais nada. ​Se você melhorar o tempo de resposta em ​um por cento, isso é suficiente? ​Se depois de cinco anos o tempo de ​resposta finalmente aumentar, isso é suficiente?\
​Que tal se apenas metade de ​sua equipe melhorasse seus tempos de resposta, ​mas a outra metade permanecesse a mesma? ​Metas específicas devem responder ​a pelo menos duas das perguntas que estou prestes a fazer. ​O que eu quero realizar? ​Por que isso é uma meta? ​Tem um motivo, propósito ou benefício específico? ​Quem está envolvido? Quem é o destinatário?\
​Funcionários, clientes, a comunidade em geral? ​Onde a meta deve ser entregue? ​Finalmente, até que ponto? ​Em outras palavras, quais são ​os requisitos e restrições? ​Em seguida, queremos definir metas que sejam mensuráveis, o que ​significa que podemos determinar se elas foram cumpridas objetivamente. ​A medição não é apenas uma forma de as pessoas acompanharem o progresso, ​mas também uma ferramenta para ajudar as pessoas a se manterem motivadas. ​Você pode dizer que a meta é mensurável perguntando quanto ​, quantas e como vou saber quando ela for alcançada?\
​Às vezes, o sucesso de uma meta pode ser ​medido com um simples sim ou não. ​Você aprendeu a tocar violão, sim ou não? ​Você precisará medir a maioria ​das metas que você tem com métricas. ​Métricas, o que você usa para medir ​algo como números ou figuras. ​Por exemplo, se sua meta era correr ​uma corrida de cinco quilômetros ​, a distância em quilômetros é sua métrica. ​No Office Green, ​a meta do projeto é aumentar a receita em cinco por cento. ​Nesse caso, a receita é a métrica.\
​Por fim, considere referências ou pontos de ​referência para garantir que você esteja escolhendo métricas precisas. ​Por exemplo, se sua meta geral ​é aumentar a receita, ​você pode analisar os dados do ano passado como referência para ​decidir quanto aumentar a receita este ano. ​Se a receita do ano passado aumentou em três por cento ​, um aumento de cinco por cento em ​uma economia em expansão ​seria uma meta razoável para este ano. ​Ok, então a meta é específica e mensurável, ​mas é alcançável? ​Ela pode ser alcançada de forma razoável com base nas métricas? ​Normalmente, você quer metas que ​sejam um pouco desafiadoras para incentivar o crescimento ​, caso contrário, qual é o objetivo ​da meta se nada vai mudar? ​No entanto, você não quer que seja ​muito extremo ou nunca o alcançará.\
​Você terá falhado antes mesmo de começar. ​Procure encontrar um equilíbrio entre os dois extremos. ​Por exemplo, vamos pegar a meta de correr 5K. ​Digamos que você corra regularmente 2,5 quilômetros, três vezes por semana. ​Uma meta alcançável será passar de 2,5 ​quilômetros para correr cinco quilômetros em quatro semanas. ​Uma meta inatingível pode ​ser conquistar o primeiro lugar nos 5K. ​Quero dizer, isso pode acontecer, ​mas não é provável, ​especialmente se você nunca correu uma corrida antes.\
​Mas como saber se uma meta é ​alcançável, se não é familiar? ​Uma pista para ajudá-lo a descobrir se ​sua meta é alcançável é perguntar: ​como ela pode ser alcançada? ​Divida a meta em ​partes menores e veja se ela faz sentido. ​Ir de 2,5 quilômetros para cinco quilômetros em ​quatro semanas significa aumentar sua distância em ​pouco mais de meio quilômetro por semana. ​Isso não é tão ruim, ​use o mesmo processo na meta do seu projeto Office Green. ​As empresas geralmente realizam análises trimestrais. ​Então, vamos supor que se espera que o aumento ​ocorra ao longo de um ano ou quatro trimestres.\
​Para atingir a meta, ​você precisa ver um aumento de pelo menos ​1,25% a cada trimestre, o que ​me parece bastante razoável. ​O que não seria razoável ​é estabelecer uma meta de aumentar ​as receitas em 50 por cento ou 100 por cento, ​a menos que sua pesquisa mostre que os ​negócios estão melhorando tão rapidamente. ​Seu objetivo é específico, mensurável e alcançável. ​Agora vamos ver se é relevante. ​Em outras palavras, faz ​sentido tentar alcançar esse objetivo? ​Pense em como a meta se alinha com ​outras metas, prioridades e valores. ​Pergunte se a meta parece valer a pena.\
​O esforço envolvido equilibra os benefícios? ​Ele corresponde às outras necessidades ​e prioridades da sua organização? ​Todos, desde o cliente, a equipe do projeto ​e as pessoas que finalmente usarão ​o produto, precisam ​sentir que vale a pena apoiar a meta. ​Além disso, considere o momento. ​Tanto a quantidade de tempo que o projeto levará, ​quanto os contextos econômicos e sociais mais amplos, ​podem ter grandes impactos. ​Pode haver um orçamento para concluir o projeto agora, ​mas a empresa será capaz de ​sustentar o projeto ao longo do tempo? ​Existe um público que continuará usando ​o produto ou serviço depois que ele for entregue?\
​Depois de obter as respostas para essas perguntas, ​você deve ter uma meta clara para ajudar a orientar o projeto. ​Se você ainda não se sente confiante sobre ​as metas do projeto, continue pesquisando. ​Não há problema em fazer perguntas se você tiver dúvidas. ​Comunique suas preocupações às ​partes interessadas seniores do projeto e ​ao seu supervisor direto, se você tiver um. ​Eles devem ser capazes de resolver algumas de suas preocupações para ​que você possa se sentir confiante em seguir em frente. ​Se você está se sentindo bem com ​o fato de o projeto ser relevante e ​viável, e se certificou de que ele é mensurável e tem ​os detalhes para manter você e sua equipe focados, o ​item final da lista de verificação ​é garantir que seja limitado no tempo. ​Limite de tempo significa que sua meta tem um prazo.\
​Os prazos oferecem uma maneira de acompanhar seu progresso ​; caso contrário, você nunca alcançará ​sua meta ou nunca poderá começar. O ​tempo e as métricas geralmente andam de mãos dadas, ​porque o tempo também pode ser usado como métrica. ​Estabelecer sua meta com limite de tempo oferece uma maneira de ​detalhar o quanto precisa ser realizado ao longo do tempo. ​Por exemplo, se você precisar ​aumentar as receitas até o final do ano, ​pode detalhar o quanto ​precisa aumentar a cada trimestre ​, mês e semana, e pronto. ​Específico, mensurável, atingível, relevante ​e com limite de tempo: um ​método quase infalível para criar e avaliar metas de projetos. ​Você sabe o que dizem, ​trabalhe de forma mais inteligente, não mais difícil. ​À medida que continuarmos neste módulo, ​você aprenderá sobre o escopo do projeto ​e verá como ter metas claras ​apoia todas as outras decisões ​que surgem durante um projeto.

### Lesson 8 - Metas SMART: Tornar as metas significativasSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Nesta lição, você está aprendendo a definir e criar metas e entregas mensuráveis do projeto. Agora, vamos nos concentrar nas Metas SMART.

As Metas **SMART (Specific, Measurable, Attainable, Relevant,** and **Time-bound)** são muito úteis para garantir o sucesso do projeto. Ao iniciar sua carreira no Gerenciamento de projetos, talvez você não defina diretamente as metas do projeto, mas deve ser capaz de esclarecê-las e entendê-las. As Metas SMART o ajudam a ver o escopo completo de uma meta, a determinar sua viabilidade e a definir claramente o sucesso do projeto em termos concretos.

Vamos recapitular o que discutimos no vídeo anterior, dando uma olhada no detalhamento dos critérios das Metas SMART abaixo:

<figure><img src="https://d3c33hcgiwev3.cloudfront.net/imageAssetProxy.v1/6OlXlIjhSLmpV5SI4Vi5_A_05b70303b9a6415cb209eba399439e10_C2M2L1R1-01.png?expiry=1780263713686&#x26;hmac=OmMIXhFKsaEV6coRDqo95uYrHI_WcwhfcEOi0RZEuSo" alt="Seis ícones para Metas SMART: Específicas, mensuráveis, atingíveis, relevantes e com prazo determinado"><figcaption></figcaption></figure>

* **Específico:** O objetivo não tem nenhuma ambiguidade que possa ser mal interpretada pela equipe do projeto.
* **Mensurável:** As Métricas ajudam a equipe do projeto a determinar quando o objetivo é alcançado.
* **Atingível:** A equipe do projeto concorda que o objetivo é realista.
* **Relevante:** A meta se encaixa no Plano Estratégico da organização e apoia o Termo de Abertura do projeto.
* **Vinculação no tempo:** A equipe do projeto documenta uma data para atingir a meta.

Você pode ver variações no significado de cada letra do acrônimo "SMART". (Por exemplo, você pode ver "acionável" ou "alcançável" em vez de "atingível" ou "realista" em vez de "relevante") Entretanto, a intenção geral de cada um desses termos - garantir que a meta esteja ao alcance - é sempre semelhante.

### **Foco no "M" de SMART**

Vamos nos concentrar um pouco no " **M** " de SMART, que significa **mensurável**. Ter metas mensuráveis permite avaliar o sucesso do seu projeto com base em métricas quantificáveis ou tangíveis, como valores em dólares, número de resultados, quantidades etc. As metas mensuráveis são importantes porque deixam pouco espaço para confusão em relação às expectativas das partes interessadas.

Nem todas as métricas terão valor, portanto, você terá de determinar quais métricas fazem sentido para o projeto. Por exemplo, medir quantas reuniões os engenheiros de software do seu projeto participam semanalmente pode não ser a métrica mais valiosa para uma Meta de produtividade. Como alternativa, você pode medir outros aspectos da produtividade dos engenheiros, como um determinado número de recursos criados por engenheiro ou um número específico de problemas sinalizados por dia.

### **Definição de uma meta SMART**

Vamos explorar um exemplo relacionado a tornar mensurável uma meta pessoal. Imagine que você esteja querendo mudar de carreira e estabeleceu a meta de concluir um Certificado de Carreira do Google. É possível **medir** o sucesso dessa meta porque, após concluir todo o programa, você receberá um certificado - um resultado tangível.

Agora, vamos determinar como fazer com que os elementos restantes dessa meta sejam SMART. Neste exemplo, sua meta **específica** é obter um certificado de carreira do Google . Você pode tornar essa meta **atingível** decidindo que concluirá um curso por mês. Essa meta é **relevante** porque apoia seu desejo de fazer uma mudança de carreira. Por fim, você pode tornar essa meta **vinculada** ao tempo, decidindo que concluirá o programa em seis meses.

Depois de definir cada um desses componentes, sua meta SMART se tornará: Obter um certificado de carreira do Google fazendo um curso por mês nos próximos seis meses.

### **Chave da lição**

A determinação de Métricas pode ser extremamente útil para capturar status, sucessos, atrasos e muito mais em um projeto. Como Gerente de projetos, a identificação de métricas significativas pode ajudar a mover o projeto em direção à sua meta. Além disso, ao definir cada elemento de uma meta do projeto para torná-la SMART, você pode determinar o que significa sucesso para essa meta e como alcançá-lo.

### Lesson 11 - Introdução aos OKRs

​Oi aí. Até agora, você aprendeu a ​definir e criar ​metas e resultados mensuráveis do projeto. ​À medida que você amplia sua compreensão do gerenciamento de projetos ​e das diferentes ferramentas disponíveis para ajudá-lo a ter sucesso, ​quero falar sobre uma ferramenta popular usada ​em muitas organizações e aqui no Google: ​objetivos e resultados-chave, ou OKRs. ​Neste vídeo, discutirei o que são OKRs, ​como são usados pelas organizações ​e como ajudam a concentrar o tempo ​e o esforço da equipe em atividades que impulsionam o sucesso. ​Você acabou de aprender e praticar o ​método SMART para definir as metas do projeto. ​Assim como o método SMART, ​os OKRs ajudam a estabelecer e esclarecer ​metas ou objetivos para uma organização, ​departamento, projeto ou pessoa. ​Os OKRs levam as Metas SMART um passo adiante ao combinar ​uma meta e métricas mais detalhadas para ​determinar um resultado mensurável.\
​Eles não apenas declaram claramente qual é a meta, ​mas também fornecem detalhes específicos que ​permitem medir o sucesso da meta. ​Uma maneira de pensar sobre OKRs é separar os ​diferentes componentes das Metas SMART ​e esclarecê-las ainda mais, ​em vez de agrupar tudo em uma declaração. ​Vamos detalhar isso. O O significa ​objetivo e define o que precisa ser alcançado. ​Ele descreve o resultado ou resultado desejado, ​como um aumento na retenção de clientes ​ou uma melhoria no processo de integração de funcionários. ​KR significa resultados-chave. ​Esses são os resultados mensuráveis ​que definem quando o objetivo foi alcançado.\
​Por exemplo, se seu objetivo ​é melhorar a retenção de clientes ​, o resultado chave pode ser ter um ​índice de satisfação do cliente de 90% até o final do primeiro trimestre. ​Lembre-se de que um dos critérios do SMART é a alcançabilidade, ​o que significa que é prático atingir a meta. ​Os resultados principais, no entanto, devem ser um pouco mais ambiciosos. ​Aqui no Google, nós realmente usamos OKRs para definir ​metas extensas como uma forma de ​nos desafiarmos a fazer algo que não realizamos antes. ​Se realmente alcançarmos todos os nossos principais resultados, ​talvez tenhamos tornado nossos OKRs um pouco fáceis demais. ​Vamos analisar rapidamente. ​Os objetivos definem o que precisa ser ​alcançado e descrevem o resultado desejado.\
​Os resultados principais definem como você ​saberá se atingiu ou não seu objetivo. ​Como os OKRs funcionam na prática? ​Como você os usa para gerenciar um projeto? ​As organizações geralmente definem OKRs em diferentes níveis, ​como o nível da empresa, o nível do ​departamento ou da equipe e o nível do projeto. ​Os OKRs em nível de empresa geralmente são compartilhados em ​uma organização para que ​todos tenham clareza sobre as metas da empresa. ​Eles geralmente são atualizados anualmente para ajudar a ​conduzir a organização na direção que ela deseja seguir. ​Esses OKRs de alto nível ​apoiam a missão da organização.\
​Os OKRs em nível de projeto devem apoiar ​e estar alinhados com os OKRs em nível de empresa. ​Um exemplo de um objetivo de nível empresarial ​na Office Green é aumentar a ​retenção de clientes adaptando-se ​às mudanças no ambiente de trabalho. ​Essa é uma meta grande e ambiciosa que ​se aplica a toda a empresa e a todos os seus empreendimentos. ​Para concentrar seus esforços para alcançar esse objetivo, a ​Office Green pode desenvolver resultados chave que ​incluam 95 por cento dos ​tíquetes de suporte ao cliente por telefone, chat e e-mail ​são resolvidos durante o primeiro contato. ​As três novas ofertas mais solicitadas para ​ambientes de escritório distribuídos estão em fase ​piloto até o final do segundo trimestre, ​e os canais de vendas e suporte estão ​disponíveis 24 horas por dia, 7 dias por semana, até o final do ano. ​Alguns desses resultados-chave em nível de empresa ​podem se tornar a base para projetos. ​Por exemplo, o principal resultado, ​“as três ​novas ofertas mais solicitadas para ​ambientes de escritório distribuídos que estão em fase ​piloto até o final do segundo trimestre”, ​pode se tornar o projeto Plant Pals.\
​OKRs em ​nível de equipe ou departamento ​apoiam os OKRs mais amplos da empresa e ajudam a impulsionar o desempenho da equipe. ​Os departamentos também podem desenvolver OKRs ​mais específicos para sua função de trabalho. ​Por exemplo, o resultado chave no nível da empresa, “os ​canais de vendas e suporte estão disponíveis ​24 horas por dia, 7 dias por semana, até o final do ano”, pode levar a ​um objetivo relacionado ao departamento de vendas, ​como: aumentar a presença da equipe de vendas em todo o país. ​E o principal resultado: novos escritórios de vendas ​serão abertos em 10 cidades até o final do ano. ​OKRs em nível de projeto são definidos durante a ​fase de iniciação para ajudar a definir metas mensuráveis do projeto. ​Eles são monitorados ao longo dos ​estágios de planejamento e execução para medir o sucesso do projeto. ​Os OKRs em nível de projeto precisam se alinhar e ​apoiar os OKRs em nível de empresa e departamento.\
​Por exemplo, para se alinhar ao ​objetivo de toda a empresa da Office Green de aumentar a ​retenção de clientes adaptando-se ​às mudanças no ambiente de trabalho, ​um objetivo de projeto para a Plant Pals pode ser ​inscrever os clientes existentes no serviço Plant Pals. ​Um resultado chave para esse objetivo pode ser que 25% dos ​clientes existentes se inscrevam no ​piloto Plant Pals. Vamos recapitular. ​OKR significa objetivos e resultados-chave. ​Eles combinam uma meta e uma métrica ​para determinar um resultado mensurável. ​Os objetivos definem o que precisa ser ​alcançado e descrevem o resultado desejado. ​Os resultados-chave definem como ​você medirá o resultado do seu objetivo.\
​Os OKRs no nível da empresa são compartilhados ​em toda a organização para que ​todos possam alinhar e concentrar ​seus esforços para ajudar a empresa a atingir suas metas. ​OKRs em nível de projeto ajudam a definir metas mensuráveis do projeto. ​Eles precisam se alinhar e apoiar ​os OKRs em nível corporativo e departamental. ​Ótimo Agora que você tem ​uma ideia melhor do que são OKRs e como funcionam, ​você pode praticar a criação de OKRs por conta própria.

## Criação de OKRs para seu projetoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

#### Nesta lição, você está aprendendo a definir e criar metas e entregáveis mensuráveis para o projeto. Esta leitura se concentrará na criação de **objetivos e resultados-chave (OKRs)** eficazes e em como implementá-los em seu projeto.

### **O que são OKRs?**

OKR significa objetivos e principais resultados. Eles combinam uma meta e uma métrica para determinar um resultado mensurável.

<figure><img src="https://d3c33hcgiwev3.cloudfront.net/imageAssetProxy.v1/jptC7Ol7TyWbQuzpe_8lBA_03179af1c1574fc6ac2efe06c12a08f1_OKRs.png?expiry=1780263958952&#x26;hmac=0zYqsfzaPu_OUU8gBqUZ-Xx3CdbaJFhXGNC2r90fmmI" alt="Gráfico mostrando uma descrição dos Objetivos e resultados-chave"><figcaption><p>Objectives: Defines what needs to be achieved; describes a desired outcome. Key results: The measurable outcomes that objectively define when the objective has been met</p></figcaption></figure>

Os OKRs de toda a empresa são usados para definir uma meta final para toda a organização, equipe ou departamento. Os OKRs em nível de projeto descrevem os resultados específicos que cada grupo precisará alcançar para apoiar a organização.

### **OKRs e gerenciamento de projetos**

Como gerente de projeto, os OKRs podem ajudá-lo a expandir as metas do projeto e esclarecer melhor os resultados que você precisará obter do projeto para atingir essas metas. Os OKRs no nível do projeto ajudam a estabelecer o escopo apropriado para a sua equipe, para que você possa dizer "não" a solicitações que possam atrapalhar o cumprimento dos objetivos. Você também pode criar e usar OKRs no nível do projeto para ajudar a motivar a sua equipe, já que os OKRs têm o objetivo de desafiá-la a ir além do que é facilmente alcançável.

### **Como criar OKRs para o seu projeto**

#### **Defina seus objetivos**

Os objetivos do projeto devem ser aspiracionais, alinhados com as metas organizacionais, orientados para a ação, concretos e significativos. Considere a visão que você e os participantes têm para o seu projeto e determine o que deseja que a equipe do projeto realize em 3 a 6 meses.

**Exemplos:**

* Criar o software de segurança de dados mais seguro
* Melhorar continuamente a análise da Web e as conversões
* Fornecer um serviço de alto desempenho
* Criar um aplicativo disponível universalmente
* Aumentar o alcance do mercado
* Obter as melhores vendas entre os concorrentes da região

**Objetivos** sólidos atendem aos seguintes critérios. Eles são:

* Aspiracionais
* Alinhados às metas organizacionais
* Orientados para a ação
* Concretos
* Significativos

Para ajudar a moldar cada objetivo, pergunte a si mesmo e à sua equipe:

* O objetivo ajuda a atingir as metas gerais do projeto?
* O objetivo está alinhado com os OKRs da empresa e do departamento?
* O objetivo é inspirador e motivador?
* A realização do objetivo causará um impacto significativo?

#### **Desenvolva os principais resultados**

Em seguida, adicione de 2 a 3 resultados-chave para cada objetivo. Os principais resultados devem ter prazo determinado. Eles podem ser usados para indicar a quantidade de progresso a ser alcançado em um período mais curto ou para definir se o objetivo foi alcançado no final do projeto. Eles também devem desafiar você e sua equipe a se esforçarem para alcançar mais.

**Exemplos:**

* X% de novas inscrições no primeiro trimestre após o lançamento
* Aumentar os gastos dos anunciantes em X% nos dois primeiros trimestres do ano
* A adoção de novos recursos é de pelo menos X% até o final do ano
* No máximo 2 bugs críticos são relatados mensalmente pelos clientes por Sprint
* Manter a taxa de cancelamento de assinatura do boletim informativo em X% neste ano civil

**Os principais resultados** sólidos atendem aos seguintes critérios:

* **Orientados** a resultados, não a uma tarefa
* Mensuráveis e verificáveis
* Específicos e com prazo determinado
* Agressivos, porém realistas

Para ajudar a moldar seus principais resultados, pergunte a si mesmo e à sua equipe o seguinte:

* O que significa sucesso?
* Que métricas provariam que alcançamos o objetivo com sucesso?

### **Práticas recomendadas de desenvolvimento de OKRs**

Aqui estão algumas práticas recomendadas que você deve ter em mente ao escrever OKRs:

* Pense em seus objetivos como sendo motivacionais e inspiradores e em seus principais resultados como sendo táticos e específicos. O objetivo descreve o que você quer fazer e os principais resultados descrevem como você saberá que fez isso.
* Como regra geral, tente desenvolver cerca de 2 a 3 resultados-chave para cada objetivo.
* Certifique-se de documentar seus OKRs e vincular-se a eles no plano do projeto.

### **OKRs versus metas SMART**

No início desta lição, você aprendeu a elaborar metas SMART para o seu projeto. Embora as metas SMART e os OKRs tenham algumas semelhanças, também há diferenças importantes. ### Lesson 15 - Determinação do escopo de um projeto

​Bem-vindo de volta. O escopo do Projeto é ​um conceito muito importante sobre o qual quero falar. ​Você ouvirá isso surgir repetidamente ​ao longo de cada fase do ciclo de vida do projeto. ​Na verdade, você pode até mesmo defendê-lo, ​então vamos nos familiarizar com o escopo. ​Neste vídeo, você ​aprenderá a definir e determinar o escopo. ​Simplificando, o escopo do seu projeto ​inclui os limites de um projeto. ​A forma como definimos isso no Google é ​“um entendimento acordado sobre o que está ​incluído ou excluído de um projeto”.\
​Escopo ajuda a garantir que ​seu projeto seja claramente definido e mapeado. ​Isso significa saber exatamente para quem o projeto será ​entregue e quem ​usará o resultado final do projeto. ​Você também precisa ter uma compreensão firme ​da complexidade do projeto. É ​simples com uma lista de tarefas facilmente gerenciável? ​Ou isso exigirá uma extensa pesquisa, ​várias rodadas de aprovações ​e um processo de produção em grande escala ​que levará anos para ser concluído? O ​escopo também inclui o cronograma, o ​orçamento e os recursos do projeto. ​Você precisa defini-las claramente para ​ter certeza de que está ​trabalhando dentro desses limites e ​do que é realmente possível para o projeto funcionar. Um ​escopo mal definido ou grandes mudanças em ​seu escopo podem causar alterações no orçamento, no ​cronograma ou até mesmo no resultado final do projeto.\
​Vamos dar uma olhada no escopo do ​seu projeto Office Green como exemplo. ​Como lembrete, o novo serviço Plant Pals ​oferece aos clientes ​plantas pequenas e de baixa manutenção, como cactos e ​samambaias frondosas, que eles podem colocar em suas mesas. ​Os clientes podem encomendá-las on-line ou a partir de ​um catálogo impresso, e o Office Green ​enviará as plantas diretamente para o endereço comercial do cliente. ​O que deve ser considerado para seu escopo, então, ​pode ser fornecer ou não plantas de reposição; ​quais segmentos de clientes receberão o serviço; ​se o catálogo on-line é um aplicativo, ​um site ou ambos; ​e como garantir que os clientes possam ​comprar do catálogo on-line, ​seja por telefone, PC, ​Mac, iPhone ou Android. ​Você também pode considerar ​as dimensões do catálogo de papel e ​se ele precisa ser colorido ou ​preto e branco e em que tipo de papel. ​Agora, como você realmente ​descobre o escopo do seu projeto? ​É simples: converse com seus patrocinadores e partes interessadas, ​entenda quais são suas metas e descubra o que é, ​e isso é realmente importante, ​o que não está incluído no projeto.\
​Abordamos várias ​maneiras diferentes de ajudar você a determinar o escopo. ​Aqui estão mais algumas perguntas úteis para adicionar à lista. ​De onde veio o projeto? ​Por que isso é necessário? O que se ​espera que o projeto alcance? ​O que o patrocinador do projeto tem em mente? ​Quem aprova os resultados finais?\
​Agora você realmente estará pronto. ​Quanto ao tempo, a definição ​do escopo do projeto deve acontecer durante ​o estágio inicial de planejamento. ​Você deve começar a descobrir o escopo desde o início, para ​que todos possam concordar com o mesmo conjunto de expectativas. ​Isso ajudará a mitigar os riscos ​de grandes mudanças futuras. ​Embora você sempre possa ajustar o escopo à medida que o ​planejamento continua, se necessário. ​Depois de entender o escopo do seu projeto, ​você deve documentar todos os detalhes para que qualquer pessoa ​possa consultá-los ​durante todo o ciclo de vida do projeto. ​Falaremos sobre algumas das melhores práticas ​para isso no final deste módulo.\
​Vamos recapitular: um escopo claramente definido ​descreve todos os detalhes de ​um projeto e regula o que pode ser ​adicionado ou removido à medida que ele avança. ​Embora, em última análise, seja ​responsabilidade do gerente de projeto monitorar ​o projeto e garantir que ​todo o trabalho e os recursos estejam dentro de seu escopo, ​os membros da equipe e as partes interessadas ​podem ser incentivados ​a fazer sua parte concentrando-se na tarefa ​mais importante para alcançar a meta do projeto. ​O próximo vídeo fala sobre os conceitos ​de “dentro do escopo” e “fora do escopo” ​e o fenômeno chamado “desvio do escopo”. ​Todos os três ajudarão a garantir que seu projeto permaneça ​em dia e dentro do orçamento. ### Lesson 16 -Coleta de informações para definir o escopoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Nesta lição, você aprenderá a definir o status do escopo do projeto e a diferenciar os fatores dentro do escopo, fora do escopo e Aumento do escopo que afetam o alcance da meta do projeto. Vamos nos concentrar aqui em como identificar os elementos vitais do escopo de um projeto e examinar as perguntas certas a serem feitas para defini-lo.

### **Fazendo perguntas sobre a definição do escopo**

Imagine que, ao trabalhar em um grupo de gerenciamento de restaurantes, seu gerente ligue e peça para você "atualizar o espaço do refeitório" e, em seguida, desligue rapidamente o telefone sem fornecer mais instruções. Nessa transferência inicial do gerente, você está perdendo muitas informações. Como você sabe o que perguntar?

Vamos recapitular rapidamente o conceito de escopo. O escopo fornece os limites do seu projeto. Você define o escopo para ajudar a identificar os recursos necessários, os custos dos recursos e um cronograma para o projeto.

Na situação que acabamos de descrever, aqui estão algumas perguntas que você pode fazer ao seu gerente para obter as informações necessárias para definir o escopo do projeto:

#### Partes interessadas

* Como você chegou à decisão de atualizar o espaço de refeições?
* A solicitação veio do proprietário do restaurante, dos clientes ou de outras partes interessadas?
* Quem aprovará o escopo do projeto?

#### Objetivos

* Qual é o motivo para atualizar o espaço para refeições?
* O que não está funcionando no espaço de refeições atual?
* Qual é a meta final deste projeto?

#### Produtos a serem entregues

* Qual espaço de refeições está sendo atualizado?
* O que exatamente precisa ser atualizado?
* O espaço do refeitório precisa de uma reforma?

#### Recursos

* Quais materiais, equipamentos e pessoas serão necessários?
* Será necessário contratar empreiteiros?
* Será necessário obter uma planta baixa e alvarás de construção?

#### Orçamento

* Qual é o orçamento do projeto? Ele é fixo ou flexível?

#### Cronograma

* Quanto tempo temos para concluir o projeto?
* Quando o projeto precisa ser concluído?

#### Flexibilidade

* Qual é o grau de flexibilidade?
* Qual é a maior prioridade: cumprir o prazo, respeitar o orçamento ou garantir que o resultado atenda a todas as metas de qualidade?

### **Principais conclusões**

Reservar um tempo para fazer perguntas e garantir que você entenda o escopo do projeto ajudará a reduzir despesas, retrabalho, frustração e confusão. Certifique-se de entender _quem_, _o que_, _quando_, _onde_, _por que_ e _como_ se aplica ao escopo. Se estiver faltando alguma dessas informações, concentre suas perguntas nesses elementos. A fase de iniciação do projeto estabelece a base para o projeto, portanto, é essencial garantir que você entenda o escopo e as expectativas durante esse estágio.

### Lesson 17 -Monitorar e manter o escopo de um projeto

​Oi aí. Como você já sabe, ​uma parte importante do gerenciamento de projetos ​é ficar de ​olho no escopo do projeto e saber quais tarefas ​são realmente parte do plano e quais não são. As ​tarefas incluídas no projeto e que contribuem para ​a meta geral do projeto são consideradas dentro do escopo. ​As tarefas que não estão incluídas são chamadas de fora do escopo. ​É seu trabalho como gerente de projeto definir e manter ​limites firmes para seu projeto ​, para que sua equipe possa se manter no caminho certo. ​Por exemplo, se os redatores ​ou designers do catálogo Plant Pals tivessem ​a ideia de expandir o tipo ​de plantas oferecidas aos principais clientes, ​você teria que ressaltar que a ​sugestão deles está fora do escopo ​e levaria ​mais tempo e aumentaria seus custos orçamentários. ​À medida que avança no ciclo de vida do projeto, ​você encontrará desafios inesperados ​ou receberá novos detalhes ou ideias ​que podem afetar o sucesso do seu projeto.\
​Mudanças, crescimento e fatores não controlados que afetam o ​escopo de um projeto a qualquer momento após ​o início do projeto são chamados de “variação do escopo”. ​Aumento do escopo é um problema comum ​e nem sempre é fácil de controlar. ​É algo com o qual lutamos em cada projeto. ​Isso pode acontecer em qualquer projeto, em qualquer setor. ​Imagine que você está trabalhando em ​uma empresa de tecnologia e ​seu projeto envolve trabalhar com designers ​e engenheiros para atualizar ​o design dos ícones da linguagem em ​um aplicativo de teclado móvel para smartphone. ​Enquanto a equipe está fazendo a atualização, ​eles percebem que o ícone de pesquisa e ​o ícone de entrada de voz também precisam de uma atualização de design. ​Esses são recursos muito pequenos e, embora ​tecnicamente não estejam no escopo, ​a equipe acha que seria necessário ​um esforço mínimo e forneceria muito valor.\
​Então, eles vão em frente e fazem as atualizações. ​Durante uma análise das partes interessadas, ​foi apontado que há um teclado em inglês, ​mas não há teclados para outros idiomas, ​e a sugestão é feita ​para criar teclados adicionais. ​Neste ponto, o escopo do projeto corre o ​risco de se expandir de ​uma atualização de ícone bastante simples para ​uma implantação complexa de vários layouts de teclado. ​Adicionar os teclados afetaria os cronogramas da equipe, ​fazendo com que o projeto demorasse mais para ser concluído. ​Isso também afetaria os ​recursos, porque você precisaria contratar ​mais pessoas ou os membros existentes da equipe ​teriam que trabalhar horas extras. ​E isso aumentaria o orçamento, ​já que a equipe não previu ​custos com horas extras de trabalho ou traduções de teclado. ​Este é apenas um exemplo de desvio do escopo.\
​Às vezes, é sutil (“Basta criar ​mais um ou dois ícones!”) ou mais óbvio (“Ei, ​você pode continuar ​criando teclados para outros idiomas?”) ​Ao identificar desvios de escopo e ser proativo, ​você protege seu projeto e sua equipe de projeto. ​Para ajudar você a combater o desvio ​do osciloscópio, é bom saber ​que ​ele vem de duas fontes principais: externa e interna. ​As fontes externas de fluência do osciloscópio são mais fáceis de reconhecer. ​Por exemplo, se você estiver trabalhando em ​um projeto com um cliente principal, ​o cliente pode solicitar ​mudanças, o ambiente de negócios ​ao seu redor pode mudar ou ​a tecnologia subjacente que você está usando pode mudar. ​Embora você não possa controlar tudo o que acontece, ​há algumas dicas úteis que você deve ter em mente.\
​Primeiro, certifique-se de que as partes interessadas ​tenham visibilidade do projeto. ​Você quer que eles saibam os detalhes ​do que será produzido, ​quais recursos são necessários, ​quanto custará ​e quanto tempo levará. ​Além disso, obtenha clareza sobre os requisitos e peça ​críticas construtivas à proposta inicial do produto. ​É importante obter essas informações ​antes da assinatura de qualquer contrato. ​Certifique-se de definir regras básicas e expectativas para o ​envolvimento das partes interessadas assim que o projeto for iniciado. ​Chegue a um acordo sobre cada uma de suas funções e ​responsabilidades durante a execução e as análises de status. ​Depois de esclarecer o escopo do projeto, ​elabore um plano de como ​lidar com solicitações fora do escopo.\
​Concorde sobre quem pode fazer solicitações formais de mudança e como ​essas solicitações serão ​avaliadas, aceitas e executadas. ​E, finalmente, certifique-se de obter esses acordos por escrito. ​Dessa forma, você sempre terá ​a documentação para indicar se você, ​uma parte interessada ou o cliente ​tiverem uma discordância no futuro. ​Uma das principais causas do desvio externo do escopo ​é não ter clareza sobre ​os requisitos antes de definir o escopo ​e obter aprovação formal ​para prosseguir com o projeto. ​É aqui que essas metas e ​resultados específicos e mensuráveis entram em jogo. ​Se os requisitos não forem específicos e se você ​não tiver concordado com os processos, os ​resultados e os marcos do projeto, é quase certo que você ​lidará com o desvio de ​escopo quando o projeto começar. ​As fontes internas de fluência do osciloscópio são ​mais difíceis de detectar e controlar.\
​Esse tipo de engano vem de ​membros da equipe do projeto que ​sugerem ou até insistem em ​mudanças ou melhorias no processamento ou no produto. ​É possível que um desenvolvedor ​de produto justifique uma decisão com base em tornar o produto melhor, ​mesmo que isso custe mais, ​ou que um líder de equipe decida que ​um determinado processo é mais eficiente sem ​perceber o impacto que a mudança no processo terá ​sobre outros membros da equipe ​encarregados de diferentes partes do projeto. ​O que você precisa deixar claro para sua equipe é que ​qualquer mudança fora ​do escopo do projeto prejudica os resultados, ​ameaça o cronograma e aumenta o risco. ​Não há pequenos impactos no escopo do projeto. ​Sempre que um membro da equipe assume uma tarefa não planejada, ​perde-se mais do que ​apenas o tempo gasto trabalhando nessa tarefa. ​É sua responsabilidade, como ​gerente de projeto, ​manter os limites do projeto. ​A melhor defesa é conhecer ​todos os detalhes do seu projeto para que você esteja ​sempre preparado com a resposta mais adequada ​a uma nova ideia ou solicitação.\
​Vamos recapitular. Monitore o escopo do seu projeto ​e proteja-o a todo custo. ​Mesmo a menor alteração pode significar um ​grande risco para o sucesso do seu projeto. ​A seguir, falarei sobre ​o modelo de restrição tripla e como você ​pode usá-lo para ajudar a determinar ​como as mudanças do seu projeto afetam o escopo. ​Fique atento.

### Lesson 18 - Estratégias para controlar o desvio de escopoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Nesta lição, discutimos a importância de definir e documentar o escopo de um projeto e como identificar os fatores de aumento do escopo que podem afetar o alcance da meta do projeto. Nesta leitura, vamos nos concentrar em como controlar o aumento do escopo.

### **Práticas recomendadas de gerenciamento do escopo**

O escopo de um projeto pode sair do controle rapidamente - tão rapidamente que talvez você nem perceba. **Aumento do escopo** é quando o trabalho de um projeto começa a crescer além do que foi originalmente acordado durante a fase de iniciação. O Aumento do escopo pode causar estresse em você, na sua equipe e na sua organização, e pode colocar o projeto em risco. Os efeitos do Aumento do escopo podem prejudicar todos os aspectos do projeto, desde o cronograma até o orçamento, os recursos e, por fim, seu sucesso geral.

Aqui estão algumas práticas recomendadas para o Gerenciamento do escopo e o controle do desvio de escopo:

* **Defina os requisitos de seu projeto.** Comunique-se com as partes interessadas ou clientes para descobrir exatamente o que eles querem do projeto e documente esses requisitos durante a fase de iniciação.
* **Defina um cronograma claro para o projeto.** O gerenciamento do tempo e das tarefas é essencial para se ater ao escopo do projeto. Seu cronograma deve descrever todos os requisitos do projeto e as tarefas necessárias para alcançá-los.
* **Determine o que está fora do escopo.** Certifique-se de que as partes interessadas, os clientes e a equipe do projeto entendam quando as alterações propostas estão fora do escopo. Chegue a um acordo claro sobre os possíveis impactos no projeto e documente seu acordo.
* **Forneça** **alternativas.** Sugira soluções alternativas ao seu cliente ou participante. Você também pode ajudá-los a considerar como as mudanças propostas podem criar riscos adicionais. Realize uma Análise de custo-benefício, se necessário.
* **Estabeleça um processo de controle de mudanças.** Durante o curso de seu projeto, algumas mudanças são inevitáveis. Determine o processo de como cada mudança será definida, revisada e aprovada (ou rejeitada) antes de adicioná-la ao Plano do projeto. Certifique-se de que sua equipe de projeto esteja ciente desse processo.
* **Aprenda a dizer não.** Às vezes, você terá de dizer não às mudanças propostas. Dizer não a uma parte interessada ou a um cliente pode ser desconfortável, mas pode ser necessário para proteger o escopo e a qualidade geral do projeto. Se lhe pedirem para assumir tarefas adicionais, explique como elas interferirão no orçamento, no cronograma e/ou nos recursos definidos nos requisitos iniciais do projeto.
* **Colete** **os custos do trabalho fora do escopo.** Se for necessário um trabalho fora do escopo, certifique-se de documentar todos os custos incorridos. Isso inclui os custos do trabalho indiretamente afetado pelo aumento do escopo. Não se esqueça de indicar para que servem as cobranças.

### **Principais conclusões**

Só é possível evitar o Aumento do escopo se todos os envolvidos no projeto entenderem e concordarem com as responsabilidades, os limites e os cronogramas. Evitar o desvio de escopo também requer comunicação clara, gerenciamento de expectativas e um caminho bem definido para o resultado desejado. Seguir as estratégias discutidas aqui pode ajudá-lo a gerenciar proativamente o desvio de escopo antes que ele se instale em seu projeto!

### Lesson 19 - Gerenciar mudanças no escopo de um projeto

​Oi, e bem-vindo de volta. ​Neste vídeo, falaremos sobre o gerenciamento do escopo do projeto. ​Gerenciamento do escopo anda de mãos dadas com a definição de metas. ​Por exemplo, redefinir o escopo pode mudar a meta, e ​uma revisão da meta pode mudar o escopo. ​O conceito de escopo do projeto é importante em todo o projeto. ​Embora seu projeto tenha suas próprias metas específicas, a meta geral para você, ​como gerente de projeto, é entregar o projeto de acordo com os acordos de escopo. ​Isso inclui a entrega do projeto dentro do prazo determinado e ​do orçamento aprovado.\
​Você descobrirá rapidamente que é mais fácil falar do que fazer. ​À medida que avança em seu projeto, ​você precisará continuamente fazer concessões e ponderar as compensações à ​medida que novos desafios, mudanças e fatores se apresentarem. ​Sempre que um membro da equipe assume uma tarefa não planejada, ​perde-se mais do que apenas o tempo gasto trabalhando nessa tarefa. ​Para decidir se uma mudança de escopo é aceitável e qual impacto ela terá, ​os gerentes de projeto geralmente se referem ao modelo de restrição tripla. ​O modelo de restrição tripla é a combinação das três ​restrições mais significativas de qualquer projeto: escopo, tempo e custo. ​Falamos um pouco sobre o que é escopo, então vamos nos concentrar agora no tempo e no custo. O ​tempo se refere ao cronograma e aos prazos do projeto. O custo inclui o orçamento ​e também cobre os recursos e as pessoas que trabalharão no projeto.\
​Tanto o tempo quanto o orçamento devem ser cuidadosamente gerenciados junto com o escopo. ​Todos os três estão vinculados; ​você não pode mudar um sem causar impacto nos outros. ​Por exemplo, uma redução no custo significa uma mudança no tempo ou no escopo. ​Um aumento no tempo significa uma mudança no escopo ou no custo, ou em ambos. ​Entender como a mudança de uma afeta as outras duas restrições é fundamental. ​É importante considerar quais compensações você está disposto a fazer à medida que o projeto avança. ​Para fazer isso com sucesso, você precisa ter uma compreensão clara das prioridades do projeto.\
​Você precisa saber o que é mais importante quando se trata de escopo, tempo e custo. ​Se houver um prazo específico que precise ser cumprido, você precisará limitar ​as alterações no escopo que possam fazer com que o projeto ultrapasse o prazo. ​Se o produto precisar parecer ou funcionar de uma determinada maneira ​, os requisitos são uma prioridade e você poderá justificar mudanças no custo ou ​no tempo para atender aos requisitos do escopo. ​Mas só porque você pode fazer uma mudança, ​isso não significa necessariamente que você deva fazer uma mudança. ​E mesmo que os limites de escopo, tempo e custos tenham sido definidos, ​você ainda pode fazer alterações se houver um bom motivo para fazer isso. ​Não se preocupe, você não precisará decidir sobre essas mudanças sozinho. ​Se houver decisões de escopo que precisem ser tomadas, o gerente de projeto provavelmente ​precisará consultar o patrocinador do projeto e as partes interessadas para obter suas aprovações.\
​Vamos analisar alguns cenários para que você possa se familiarizar com a ponderação do valor ​de uma troca e entender os impactos de qualquer mudança. ​No primeiro cenário, ​foi feita uma solicitação para melhorar as características do produto Plant Pals. ​O diretor de produto da Office Green deseja usar vasos que indiquem ​quando as plantas precisam ser regadas. ​Fazer alterações no produto é uma mudança de escopo. ​Você sabe que não pode alterar o orçamento, mas pode estender o cronograma. ​Assim, você pode aceitar as solicitações de mudança de escopo e estender o cronograma, ​desde que o orçamento não aumente. ​Aqui está outro cenário possível. Foi feita uma solicitação para reduzir ​o orçamento sem fazer alterações no escopo.\
​O resultado final de Plant Pals ainda precisa ter a aparência e o ​funcionamento que todos vocês concordaram originalmente. ​Se você quiser reduzir o orçamento e manter o escopo, ​talvez seja necessário estender o cronograma. ​Ok, aqui está outro cenário. Há uma solicitação para restringir o cronograma e ​terminar mais cedo, mas você não pode aumentar o orçamento. ​Para fazer isso, você precisa fazer alterações no escopo, ​como limitar as opções de envio. ​Isso dará mais tempo ao seu projeto, ​porque você terá um contrato de envio a menos para negociar. ​O resultado final não será exatamente o que foi originalmente acordado, mas ​significa divulgá-lo mais cedo, conforme solicitado e dentro do orçamento.\
​Vamos tentar mais um. Neste último cenário, o Diretor de Produto informa ​que o prazo do projeto deve ser cumprido — é a coisa mais importante. ​Nesse caso, suas partes interessadas estão dispostas a aumentar o orçamento e ​fazer as alterações necessárias nos requisitos do escopo para ​cumprir o prazo. ​No final das contas, tudo se resume a priorizar qual elemento do triângulo é ​mais importante no projeto. ​Você está entendendo os trade-offs? ​Ter em mente o escopo, o tempo e o custo ao gerenciar seu projeto o ajudará a ​navegar por diferentes condições e, ao mesmo tempo, atingir suas metas. ​Lembre-se de que a mudança é inevitável ao gerenciar projetos, ​e entender esse framework pode ajudá-lo a planejar e ​se comunicar adequadamente para que seu projeto seja bem-sucedido.\
​Ao entender o modelo de restrição tripla, ​você terá as ferramentas para avaliar as mudanças no escopo. ​Entender como as mudanças serão avaliadas, aceitas e ​executadas é a chave para o gerenciamento do escopo. ​Não se preocupe se você ainda tiver dúvidas. ​Com certeza falaremos mais sobre esse conceito no Curso 4. A ​seguir, falaremos mais sobre como lançar e realizar ​seu projeto com sucesso. Te vejo em breve!

### Lesson 21 - Lançamento e aterrissagem de um projeto

​Bem vindo de volta. ​Neste ponto, você aprendeu um pouco sobre como definir Metas SMART, ​além de definir e gerenciar o escopo. ​Pode ser tentador pensar que você está pronto para iniciar este projeto com ​essas duas peças importantes, ​mas há um elemento comum que garante que você alcance ​essas metas dentro do escopo. ​E esse elemento-chave é saber quando seu projeto é entregue e ​você pode considerá-lo um sucesso. ​Muitas pessoas acham que o momento de decidir se um projeto ​é bem-sucedido é quando você produz o resultado final e o apresenta ao cliente. ​Isso está chegando perto. ​Entregar o resultado final do seu projeto ao cliente ou ​usuário é o que chamamos de lançamento do projeto.\
​Você termina de construir ou criar um projeto, as tarefas são concluídas e ​as entregas são concluídas. ​Você atingiu seu objetivo. ​O projeto é bem-sucedido e considerado concluído nesse sentido, mas ​funciona bem? ​Alcançou o resultado desejado? ​O verdadeiro fator decisivo do sucesso do projeto é quando você ​testa o resultado final. ​A aterrissagem é quando você realmente mede ​o sucesso do seu projeto usando os critérios de sucesso estabelecidos no início do projeto. ​Essa é uma parte crucial do estabelecimento de metas, que geralmente é negligenciada ​na fase de iniciação.\
​Por exemplo, pense em fazer uma viagem de avião. ​Não basta que o piloto consiga tirar o avião do chão. ​Para chegar com segurança ao seu destino, eles precisam saber como pousar. ​Seu sucesso deve continuar além do ponto de entrega do projeto final. ​Você precisa ser capaz de medir se o projeto funciona conforme o esperado ​depois de colocado em prática. ​Vamos dar o exemplo do seu projeto Plant Pals. ​Você conseguiu lançar o novo serviço com sucesso, o site foi lançado, ​os catálogos foram impressos e ​entregues, os pedidos foram recebidos e a receita está começando a aumentar.\
​Seria fácil chamar isso de vitória e seguir em frente. ​Mas o que acontece se os clientes ficarem insatisfeitos quando as plantas forem entregues? ​E se as plantas começarem a murchar e descolorir depois de algumas semanas? ​Só porque lançar o projeto e lançá-lo parece um sucesso ​no papel, isso não significa que o projeto tenha conseguido se concretizar. ​Para a maioria dos projetos, o lançamento em si não é uma medida significativa de sucesso. ​É o que vem depois do lançamento que realmente conta. ​Os lançamentos são apenas um meio para atingir um fim, e olhar além do lançamento é importante ​para garantir que o lançamento atinja suas metas gerais.\
​Se você começar a olhar além do lançamento até a aterrissagem, ​é mais provável que chegue aonde está tentando ir. ​Como a aterrissagem é um conceito e não uma definição finita, é importante ​definir como é uma aterrissagem bem-sucedida para um projeto específico. ​Felizmente, temos uma maneira de medir e ajudar você a garantir o sucesso do seu projeto. ​Isso é chamado de critério de sucesso e, se você conseguir segui-lo ​durante todo o ciclo de vida do seu projeto, acabará tendo uma aterrissagem tranquila. ​Os critérios de sucesso incluem todos os detalhes específicos de suas metas e ​resultados, e podem ser um guia para que ​você saiba se realizou o que se propôs a fazer. ​Critérios de sucesso definirão padrões de como seu projeto será julgado. ​No próximo vídeo, descreverei o que você precisa saber ​sobre definir critérios de sucesso e comunicar o sucesso do projeto. ### Lesson 21.1 - Não se esqueça de aterrissar: Medindo o sucesso do projetoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Nesta lição, você aprenderá a distinguir a diferença entre o lançamento de um projeto e o Destino de um projeto. Vamos nos concentrar aqui na diferença entre lançamentos e Destinos e em como garantir que seu projeto seja concluído com sucesso.

É comum ouvir empresas comemorando o lançamento de um novo produto, serviço ou iniciativa, e é importante lembrar que, mesmo quando seu projeto está no mercado, seu trabalho não está concluído. Ao trabalhar em um projeto, a meta não é simplesmente lançá-lo, mas sim aterrissar . O Destino ocorre quando seu projeto alcança uma medida de sucesso. Como Gerentes de projetos, o Destino é o que buscamos e o que celebramos. Eles são a recompensa final de todos os nossos esforços.

### **Lançamento vs. Destino de um projeto**

No Gerenciamento de projetos, o "lançamento" de um projeto significa que você entregou os resultados finais do projeto ao cliente ou usuário. No entanto, não se pode basear o sucesso do projeto apenas no momento em que o cliente o aceita. Seu trabalho em um projeto não estará concluído até que você o "Destino" meça minuciosamente os resultados. É nesse momento que os **Critérios de sucesso** e as Métricas que você definiu inicialmente ao estabelecer as Metas SMART serão úteis.

As equipes devem ter clareza sobre o que estão tentando realizar, além de apenas lançar algo para os usuários. Seu projeto aumentará a retenção? Seu projeto acelerará um recurso do produto? Dependências do produto e da situação, as respostas serão diferentes, mas é importante que sua equipe se alinhe e trabalhe para atingir a mesma meta mensurável.

### **Lançamento primeiro, Destino depois**

Vamos considerar um exemplo: imagine que você é Gerente de projetos de uma organização ecológica. Sua organização pede que você crie um Treinamento para alunos do ensino médio em seu município para ensiná-los sobre os impactos da reciclagem. A meta do município é aumentar a reciclagem em 20% nos próximos cinco anos. Você reúne sua Equipe e começa a desenvolver o conteúdo de aprendizagem para criar esse programa de treinamento. Você e sua Equipe levam um ano para concluir a pesquisa, o desenvolvimento e a Produção desse treinamento. Ao entregar o Treinamento para o distrito escolar, você está lançando o projeto. Para saber se o seu projeto realmente atingiu a meta pretendida, é necessário verificar periodicamente nos próximos cinco anos para ver se o programa de treinamento está no caminho certo para produzir um aumento de 20% na reciclagem no município.

### **Lançamento e esquecimento**

Um erro comum de muitas Equipes de Projeto é "lançar e esquecer" os resultados. Isso acontece quando um Gerente de projeto entrega o projeto ao cliente e o cliente aceita a entrega do projeto, mas o Gerente de projeto não avalia se as entregas do projeto satisfazem o cliente ou o usuário. No exemplo acima, se você não fizesse uma verificação periódica ao longo de cinco anos para avaliar os resultados, teria apenas lançado - mas não lançado - o projeto. O Lançamento e o Destino trabalham em conjunto para garantir o verdadeiro sucesso.

A aterrissagem de um projeto não deve criar mais obstáculos. Se feito corretamente, o Destino cria um Alinhamento maior dentro das Equipes sobre os resultados finais que todos desejam e dá a todos na equipe uma melhor visibilidade sobre como alcançar o sucesso.

### **Principais conclusões**

O lançamento do seu projeto para o cliente pode ser um momento muito importante para você. Você entregou o projeto ao cliente e agora pode dar um passo atrás e respirar. No entanto, certifique-se de que seu projeto também está sendo lançado. Examine suas anotações, converse com sua equipe, reúna-se com o cliente e lembre-se de voltar às entregas e às Métricas pretendidas para ajudá-lo a medir o sucesso.

### Lesson 22 - Definição de critérios de sucesso

​Olá de novo. ​Aprendemos sobre as diferenças entre lançamento e aterrissagem ​e também aprendemos sobre as diferenças entre entregar seu ​projeto e descobrir se o resultado funciona conforme o esperado. ​Mas como exatamente você sabe que seu projeto é um sucesso? ​Como você sabe se você realmente aterrissou? ​No início do projeto, você definiu metas e ​resultados que são mensuráveis, o que significa que você pode determinar se eles foram atingidos. ​Da mesma forma, você precisa definir critérios de sucesso que também possam ser medidos para ​que você saiba se eles foram atendidos. ​Os critérios de sucesso dirão se ​o projeto como um todo foi bem-sucedido ou não.\
​Eles são os detalhes específicos de suas metas e ​resultados que indicam se você realizou o que se propôs a fazer. ​Eles são os padrões pelos quais o projeto será julgado depois de ​entregue às partes interessadas e aos clientes. ​Definir critérios de sucesso também esclarece para sua equipe o que eles estão tentando ​realizar além de simplesmente lançar algo para os usuários. ​É para aumentar a satisfação do cliente com o serviço para ​que ele possa continuar comprando mais produtos? ​Melhorar um recurso existente para reter clientes? ​Dependendo do projeto, as respostas serão diferentes. ​Mas é importante que a equipe esteja alinhada e trabalhando em prol de uma meta compartilhada.\
​Às vezes, forçar a conversa e esclarecer o resultado final ​pode trazer à tona questões e áreas de discordância. ​Não há um processo definido para determinar os critérios de sucesso, mas ​vou detalhar alguns pontos-chave a serem considerados. ​Lembra da parte mensurável de suas Metas SMART? ​Uma das perguntas a serem feitas ao tornar suas metas mensuráveis é: ​Como saberei quando elas forem alcançadas? ​A mesma pergunta se aplica ao seu projeto: como você saberá quando ele estiver concluído? ​Somente nesse caso, você quer perguntar: ​Como saberei quando isso for realizado com sucesso? ​Você pode medir para determinar o sucesso do seu projeto de forma semelhante à medição de ​uma meta.\

### **Qualidade do produto**

O produto, ou resultado final, de um projeto tem seu próprio conjunto de atributos que definem o sucesso. Os atributos necessários para o sucesso do produto incluem a Integridade dos Recursos, a Qualidade dos Recursos, o Custo Unitário, a Usabilidade, etc. O fato de um produto ser completo contribuirá para o sucesso do produto. Isso pode se aplicar a qualquer projeto no qual você entrega um produto ou um resultado tangível no final. Para nos manter no caminho certo para o sucesso, podemos criar uma lista de Requisitos do produto para garantir que não falte nada. Por exemplo, se o projeto produz um software de processamento de texto, você precisa de recursos básicos como entrada de texto, formatação, salvamento e impressão. Para medir o sucesso de um produto, considere incluir essas Métricas de produtividade em sua lista de verificação:

* Acompanhamento da implementação dos Requisitos prioritários do produto
* Acompanhamento e avaliação do número de problemas técnicos ou defeitos do produto
* Meça a porcentagem de recursos entregues ou liberados no final do projeto

### Objetivos e resultados-chave (OKRs)

Você aprendeu que os OKRs - Objetivos e resultados-chave - combinam uma meta e uma métrica para determinar um resultado mensurável. A definição de OKRs é uma técnica que pode ajudar as equipes de projeto a definir, comunicar e medir critérios de sucesso compartilhados.

### **Comunicação e acompanhamento de OKRs**

A realização de check-ins regulares e o acompanhamento ativo do progresso com sua equipe podem ajudar a garantir que os objetivos sejam atingidos e que quaisquer problemas sejam resolvidos o mais rápido possível.

**Compartilhe seus OKRs com sua equipe.** Depois de criar OKRs para o seu projeto, é importante comunicá-los à sua equipe para que todos saibam como se concentrar e alinhar seus esforços. Isso pode ser feito compartilhando um documento digital, apresentando-os em uma reunião ou adicionando-os a um site interno. Os OKRs podem ajudar a sua equipe de projeto a se ater às suas metas, monitorar quais estão aquém do esperado e estar continuamente motivada para atingir os objetivos do projeto.

**Atribua proprietários.** Atribua um proprietário a cada resultado-chave para que todos saibam quem é responsável pelo quê. Isso ajuda a aumentar a clareza e a responsabilidade.

### **Medição do progresso**

O acompanhamento dos OKRs é uma parte importante do rastreamento e do compartilhamento do seu progresso. Um atalho para determinar o status de um projeto é pontuar ou classificar seus OKRs. Embora as pontuações ou notas não forneçam uma avaliação completa do sucesso de um projeto, elas são ferramentas úteis para determinar o quão perto você chegou de atingir seus objetivos. Em seguida, é possível compartilhar suas pontuações de OKRs com as partes interessadas do projeto e Membros da equipe como parte das atualizações gerais do projeto.

**Determine como você pontuará seus OKRs.** Os OKRs podem ser pontuados de diferentes maneiras. Você pode pontuar com base em uma porcentagem do objetivo concluído, na conclusão de determinados Marcos ou em uma escala de 1 a 10, por exemplo. Também é possível usar uma abordagem de pontuação de "semáforo", em que vermelho significa que não houve progresso, amarelo significa que houve algum progresso e verde significa que o objetivo foi concluído. A abordagem mais simples para pontuar OKRs é o método "sim/não", em que "sim" significa que você atingiu seu objetivo e "não" significa que não atingiu. Usando essa abordagem, um resultado-chave como "Lançamento de uma nova campanha de marketing de widget" pode ser classificado como 1 ou 0, Dependências se foi lançado (1) ou não (0). Uma abordagem de Dimensionamento mais avançada é classificar seus resultados-chave em uma escala. Com esse método, se um resultado-chave fosse "Lançamento de seis novos recursos" e apenas três novos recursos fossem lançados, o OKRs poderia ser classificado como 0,5. Geralmente, se o KR o ajudou a atingir o Objetivo, seu OKRs deve receber uma pontuação mais alta; se não ajudou, seu OKRs deve receber uma pontuação mais baixa. No Google, os OKRs geralmente são classificados em uma escala de 0,0 a 1,0, sendo que 1,0 significa que o objetivo foi totalmente alcançado. Cada resultado-chave individual é classificado e, em seguida, é calculada a média das notas para determinar a pontuação desse OKRs. **Defina suas expectativas de pontuação.** Com a Escalabilidade de 0,0 a 1,0 do Google, a expectativa é definir OKRs ambiciosos e ter como objetivo alcançar uma média de pelo menos 0,6 a 0,7 em todos os OKRs. Para OKRs classificados de acordo com a porcentagem alcançada, o ponto ideal é algo entre 60 e 70%. Uma pontuação mais baixa pode significar que a equipe não está alcançando o que poderia. Uma pontuação mais alta pode significar que as metas aspiracionais não estão sendo definidas em um nível suficientemente alto.

**Cronograma de pontos de controle.** É importante comunicar regularmente o status dos OKRs do projeto à sua equipe e aos gerentes seniores. Por exemplo, pode ser útil fazer check-ins mensais sobre o progresso dos OKRs para dar aos indivíduos e à sua equipe uma noção de onde eles estão. Normalmente, no final do Trimestre, você classificará cada um dos OKRs para avaliar o desempenho da equipe para atingir suas metas.

### **Principais conclusões**

Os OKRs podem ajudá-lo a definir e medir os Critérios de sucesso do seu projeto. Para que os OKRs sejam usados para atender efetivamente aos Critérios de sucesso do seu projeto, é importante compartilhá-los com a sua equipe, atribuir proprietários a cada resultado-chave para garantir a Responsabilidade, medir o progresso dos OKRs pontuando-os e acompanhar o progresso dos OKRs agendando check-ins regulares com a sua equipe.

### **Partes interessadas**

Ter participação em um negócio, situação ou projeto significa que você está investido em seu sucesso. Muitas vezes, haverá várias partes interessadas no resultado de um projeto. As Partes interessadas principais geralmente incluem Membros da equipe, líderes seniores e Clientes. Por exemplo, imagine que você é Gerente de projetos de uma empresa de construção que foi encarregada de construir um novo espaço para eventos para uma empresa de catering local. Um exemplo de partes interessadas secundárias pode ser o ponto de contato jurídico do projeto. Embora o resultado do projeto possa não afetá-los diretamente, o projeto em si afetaria seu trabalho quando eles processassem o contrato. Cada projeto terá um conjunto diferente de partes interessadas, e é por isso que é importante que o Gerente de projeto saiba quem são, do que precisam e como se comunicar com eles.

Lembre-se de que a escolha de colegas de equipe com as habilidades técnicas e interpessoais corretas será valiosa ao trabalhar para atingir as Metas do projeto. ### **Patrocinador**

O **Patrocinador do projeto** é outra parte interessadas principal. O patrocinador inicia o projeto e é responsável por apresentar um Business-to-business para sua existência, assinar o Termo de abertura do projeto e liberar recursos para o Gerente de projeto. O Patrocinador do projeto é muito importante para o projeto, portanto, é fundamental comunicar-se com ele frequentemente em todas as fases do projeto. Em nosso exemplo de empresa de construção, o CEO também poderia ser o Patrocinador do projeto.

### **Principais conclusões**

Embora as funções envolvidas em cada projeto variem, todos os projetos incluirão um Gerente de projetos e Partes interessadas principais que são diretamente afetadas pelo resultado do projeto, como Membros da equipe, líderes seniores, o cliente e o Patrocinador do projeto. As Partes interessadas secundárias, cujo trabalho afeta menos diretamente o projeto, também podem desempenhar uma função. Tenha essas funções em mente ao examinarmos mais de perto a importância das partes interessadas.

Nesta lição, você está aprendendo a realizar uma análise das partes interessadas e a explicar sua importância. Vamos nos concentrar aqui em como priorizar os vários tipos de partes interessadas que podem existir em um projeto, gerar a adesão das partes interessadas e gerenciar suas expectativas.

### **Realização de uma análise das partes interessadas**

**As partes interessadas** são uma parte essencial de qualquer projeto. A capacidade de um Gerente de projeto de Equilibrar os Requisitos das partes interessadas, obter sua Adesão das partes interessadas e entender quando e como envolvê-las é a chave para a realização bem-sucedida de um projeto.

É chave manter as partes interessadas organizadas para entender quando e como envolvê-las no momento certo. Em um vídeo anterior, apresentamos a **Análise das partes interessadas,** uma ferramenta útil que os Gerentes de projetos usam para entender as necessidades das partes interessadas e ajudar a minimizar os soluços durante o Ciclo de vida do projeto.

Vamos revisar as principais etapas da análise das partes interessadas:

1. Faça uma Lista de todas as partes interessadas que o projeto impacta. Ao gerar essa lista, pergunte a si mesmo: Quem está investindo no projeto? Quem é afetado por este projeto? Quem contribui para este projeto?
2. Determine o nível de interesse e influência de cada parte interessada - essa etapa o ajuda a determinar quem são as partes interessadas principais. Quanto maior o nível de interesse e Influência, mais importante será priorizar suas necessidades ao longo do projeto.
3. Avalie a capacidade de participação das partes interessadas e, em seguida, encontre maneiras de envolvê-las. Vários tipos de projetos produzirão vários tipos de partes interessadas - algumas serão **partes interessadas ativas** com mais opiniões e Touchpoints e outras serão **partes interessadas passivas,** preferindo apenas atualizações de alto nível e não envolvidas no dia a dia. Dito isso, o fato de uma parte interessada não participar com a mesma frequência que outras não significa que ela não seja importante. Há muitos fatores que desempenham um papel na determinação da capacidade de uma parte interessada de participar de um projeto, como a distância física do projeto e sua carga de trabalho atual.

**Dica de profissional:** talvez seja melhor formar um **comitê diretivo** durante alguns projetos. Um comitê diretivo é uma coleção de partes interessadas principais que têm um alto nível de poder e interesse em um projeto. Um comitê diretivo pode influenciar vários departamentos da organização, o que significa que eles têm o potencial de liberar um número maior de recursos para o Gerente de projetos.

### **Visualização de sua análise**

Uma **grade de poder** mostra o interesse das partes interessadas _no_ projeto em comparação com sua influência _sobre o_ projeto. Essa ferramenta de quatro quadrantes ajuda os Gerentes de projetos a avaliar como gerenciar as partes interessadas. Ela é usada para determinar o nível adequado de engajamento exigido pela Equipe do projeto, necessário para ganhar a confiança e a adesão das partes interessadas. A metade superior da grade representa maior Influência e a metade inferior da grade representa menor Influência. Enquanto isso, a metade esquerda da grade representa menor interesse e a metade direita representa maior interesse. Com isso em mente, o quadrante superior esquerdo é rotulado como "atende às necessidades", o quadrante superior direito como "gerencia de perto", o quadrante inferior esquerdo é rotulado como "monitora" e o quadrante inferior direito é rotulado como "demonstra consideração"

Reserve um tempo no início do projeto para estabelecer sua abordagem das partes interessadas. Liste as partes interessadas e, em seguida, coloque-as nos lugares apropriados da grade. A visualização de sua colocação o ajudará a gerenciar as comunicações e as expectativas. Ter uma ferramenta de referência rápida para orientar suas ações de comunicação também permitirá que você tenha a capacidade de passar mais tempo fazendo outras tarefas do projeto.

Para detalhar melhor, aqui está o significado de cada quadrante:

**Quadrante 1: Alta Influência, Alto Interesse (canto superior direito)**

As partes interessadas neste quadrante têm uma Influência significativa no projeto e estão altamente interessadas em seu resultado. Elas podem ter um grande impacto nas decisões e no sucesso do projeto. Os exemplos podem incluir Patrocinadores do projeto, executivos-chave ou autoridades regulatórias. As respostas para esse quadrante incluem:

1. **Engajamento e envolvimento:**
   * Mantenha essas partes interessadas bem informadas e engajadas durante todo o ciclo de vida do projeto.
   * Envolva-os nos processos de tomada de decisão, buscando sua contribuição e feedback.
   * Tratar suas preocupações com comando e eficácia.
2. **Comunicação regular:**
   * Cronograma de reuniões regulares ou atualizações para mantê-los informados sobre o andamento do projeto e quaisquer problemas.
   * Adapte a Comunicação às suas preferências e necessidades para garantir que eles continuem apoiando e se engajando.

**Quadrante 2: Alta Influência, Baixo Interesse (canto superior esquerdo)**

As partes interessadas neste quadrante têm alta Influência, mas podem não estar profundamente interessadas nos detalhes cotidianos do projeto. Elas podem incluir gerentes seniores que precisam ser informados, mas podem não estar ativamente engajados. As respostas para esse quadrante incluem:

1. **Resumos executivos:**
   * Forneça resumos de alto nível do progresso do projeto e das decisões-chave para análise.
   * Concentre-se no impacto do projeto sobre as metas e os objetivos organizacionais.
2. **Atualizações periódicas:**
   * Forneça briefings ou atualizações periódicas para garantir que eles sejam informados sobre os principais marcos e as mudanças críticas do projeto.

**Quadrante 3: Baixa Influência, Alto Interesse (canto inferior direito)**

As partes interessadas desse quadrante têm um alto interesse no projeto, mas uma Influência relativamente baixa em seu resultado. Normalmente, estão buscando atualizações e informações sobre o projeto. As respostas para esse quadrante incluem:

1. **Atualizações regulares:**
   * Comunicar o progresso, os riscos e as atualizações do projeto para mantê-los engajados e informados.
   * Responda às suas consultas e preocupações com comando para manter seu interesse.
2. **Feedback das partes interessadas:**
   * Busque o feedback deles sobre os planos de projeto, o progresso e os resultados para garantir que a perspectiva deles seja considerada.

**Quadrante 4: Baixa Influência, Baixo Interesse (canto inferior esquerdo)**

As partes interessadas desse quadrante têm baixa Influência no projeto e interesse limitado em seus detalhes. Elas podem incluir funcionários de nível inferior ou departamentos não diretamente impactados pelo projeto. As respostas para esse quadrante incluem:

1. **Comunicação geral:**
   * Compartilhe atualizações gerais sobre o progresso geral do projeto sem sobrecarregá-los com detalhes.
   * Responda a quaisquer perguntas específicas que eles possam ter, mas evite inundá-los desnecessariamente com informações relacionadas ao projeto.
2. **Engajamento mínimo:**
   * Mantenha um nível básico de comunicação e Engajamento para mantê-los cientes do projeto sem distraí-los de suas responsabilidades regulares.

Ao compreender a influência e o interesse das partes interessadas usando uma grade de energia de quatro quadrantes, os Gerentes de projeto podem adaptar suas estratégias de comunicação e Engajamento para gerenciar com eficácia os relacionamentos com as partes interessadas durante todo o Ciclo de vida do projeto.

**Dica profissional:** embora essas ferramentas ajudem a organizar as informações, elas não necessariamente fazem a diferença entre o sucesso e o fracasso do engajamento das partes interessadas. O que fará com que o envolvimento das partes interessadas seja bem-sucedido é a capacidade do Gerente de projeto de conhecer as motivações e inspirações de suas partes interessadas. Isso requer tempo, Habilidades interpessoais e insight sobre o funcionamento político interno da organização. Lembre-se de que cada projeto é diferente, e seu projeto pode precisar de ajustes ao longo do caminho à medida que você cresce como Gerente de projetos. Fazer as mudanças necessárias significa que você está fazendo algo certo. Apenas certifique-se de verificar e garantir que está no caminho certo, engajando as partes interessadas com sucesso e entregando seu projeto!

### **Geração de adesão das partes interessadas**

Depois de organizar e avaliar suas partes interessadas, é hora de começar a tomar algumas decisões sobre a adesão das partes interessadas que é absolutamente necessária para o sucesso, cujos Requisitos merecem mais atenção e qual o nível de comunicação que cada parte interessada exigirá.

Obter a adesão das partes interessadas é essencial para garantir que seu projeto não seja despriorizado ou privado de recursos.

As dicas para obter a adesão das partes interessadas principais incluem:

* Mapear claramente o trabalho do projeto para as metas das partes interessadas.
* Descrever como o projeto se alinha com as metas do departamento ou da equipe da parte interessada.
* Detectar o feedback das partes interessadas e encontrar maneiras de incorporá-lo ao Termo de Abertura do projeto, quando apropriado.

Gerencie as expectativas das partes interessadas apresentando uma visão realista das habilidades da sua equipe. Não prometa demais e entregue de menos!

### Lesson 5 - Elementos de um gráfico RACI

​No último vídeo, ​vimos como uma análise das partes interessadas ​nos mostra a melhor forma de trabalhar com ​as partes interessadas e quando nos comunicar ​com todas as diferentes pessoas envolvidas no projeto. ​Neste vídeo, vamos conferir ​outra ferramenta útil chamada Gráfico RACI. ​Um Gráfico RACI ajuda a ​definir funções e responsabilidades para ​indivíduos ou equipes para ​garantir que o trabalho seja realizado com eficiência. ​Ele cria funções claras e ​orienta cada membro da equipe. ​Há quatro tipos de ​participação incluídos em um Gráfico RACI. ​São eles: responsáveis, ​responsáveis, consultados e informados. ​Vamos dar uma olhada em cada um.\
​Responsável se refere àqueles que ​fazem o trabalho para concluir a tarefa. ​Responsável se refere àqueles ​que garantem que o trabalho seja realizado. Os ​consultados incluem aqueles que dão ​feedback, como especialistas no assunto ou tomadores de decisão. ​E, por fim, informamos, ​o que inclui aqueles que precisam apenas saber ​as decisões finais ou que uma tarefa foi concluída. ​Aqui está uma imagem de como isso se divide em forma de gráfico. ​Ao criar seu Gráfico RACI, ​você precisa anotar ​cada tarefa ou entrega do seu projeto ​e, em seguida, atribuir a ele a função apropriada ​para cada parte interessada. ​Para fazer isso, primeiro ​pense em quem está envolvido no projeto.\
​Escreva as funções ou ​os nomes das pessoas em uma linha na parte superior do gráfico. ​Dica profissional: use funções em vez de ​nomes se algumas pessoas assumirem mais de uma função. ​Em seguida, anote as tarefas ​ou os resultados em uma coluna à esquerda. ​Tente não ser muito específico aqui. ​Você quer que o gráfico seja simples e fácil de ler. ​Depois disso, analise cada tarefa e cada entrega e pergunte: ​Quem é responsável por fazer isso? ​Quem é responsável se isso não for feito?\
​Quem terá opiniões fortes a acrescentar ​e, portanto, deve ser consultado ​sobre como isso é feito? ​E quem precisa ser informado sobre ​o progresso ou as decisões tomadas sobre isso? ​Atribua as letras R, A ​, C e I com base em suas respostas. ​Por exemplo, como gerente de projeto ​no lançamento do novo serviço do Office Green, ​uma de suas tarefas é criar faixas de ​preço ​diferentes para pacotes e frequências de entrega diferentes. ​O chefe de finanças será responsável porque ​o projeto precisa se manter dentro do orçamento e ganhar dinheiro, ​mas é o analista financeiro que é responsável, ​pois ele é a pessoa que trabalha para ​determinar os preços ideais. ​O Diretor de Produto será consultado sobre ​o assunto enquanto supervisiona as ofertas de produtos. ​E, finalmente, os membros da equipe, ​como os da equipe ​de vendas, precisam ser informados sobre o preço final.\
​É possível que haja várias funções que se ​enquadrem nas categorias “informado” e “consultado”. ​Uma coisa que sempre permanecerá constante é que ​nunca haverá mais de uma pessoa ​designada como “responsável”. ​Isso evita confusão, porque ter uma pessoa ​responsável define claramente a propriedade. ​No entanto, a mesma pessoa que é ​“responsável” também pode ser “responsável”. ​Há vários outros fatores que ​podem causar confusão de papéis. ​Por exemplo, pode haver cargas de trabalho desequilibradas, ​o que significa que algumas pessoas podem estar ​trabalhando mais ou menos do que outras na equipe. ​Ou pode haver uma hierarquia pouco clara quando as pessoas não têm ​certeza de quem procurar ajuda se uma tarefa não for concluída ​ou uma propriedade pouco clara das decisões em que ​as pessoas não têm certeza de quem fará a decisão final de um projeto.\
​Outro problema pode ser a sobreposição de trabalho. ​É quando equipes ou indivíduos ​sentem que são responsáveis pelo mesmo trabalho. ​Quando isso acontece, as coisas podem ficar confusas rapidamente. ​E o mesmo vale para a comunicação excessiva. ​Embora a comunicação geralmente seja uma coisa boa, ​muita comunicação pode ​realmente complicar as coisas. ​Isso pode causar sobrecarga de informações, fazendo com ​que as pessoas não saibam no que ​prestar atenção e, portanto, perdem algo importante. ​Nossa, há muitas coisas que podem causar confusão, ​mas todos esses problemas podem ser resolvidos ​ou até mesmo evitados com uma análise RACI.\
​Seja proativo e faça esse trabalho com antecedência, ​e você ajudará a garantir o sucesso do seu projeto.

### Lesson 6 - Criação de um gráfico RACISituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Um **Gráfico RACI** pode ser uma maneira extremamente eficaz de definir as Funções do projeto, orientar cada Membro da equipe e Parte interessada e garantir que o trabalho seja realizado com eficiência. Ter um Gráfico RACI disponível durante toda a duração de seu projeto como uma visualização rápida pode ser inestimável. Nesta leitura, abordaremos a função de um gráfico RACI e seus componentes e exploraremos como os Gerentes de projetos usam os gráficos RACI para definir e documentar as funções e responsabilidades do projeto.

### **Elementos de um Gráfico RACI**

Um Gráfico RACI cria Funções claras e dá orientação a cada membro da equipe e parte interessada. Ao longo de sua carreira, você pode ouvir um Gráfico RACI ser chamado de Matriz de Atribuição de Responsabilidade (RAM), diagrama RACI, ou matriz RACI . O objetivo final desse gráfico é esclarecer a função de cada pessoa em seu projeto.

Primeiro, vamos detalhar cada uma das funções que podem ser atribuídas às pessoas:

**R**: Responsável: quem realiza o trabalho

**A**: Responsabilidade: quem garante que o trabalho seja feito

**C**: Consultado: quem fornece informações ou feedback sobre o trabalho

**I**: Informações: quem precisa saber o resultado

Observe que os Gráficos RACI podem ser organizados de diferentes maneiras, dependendo da preferência pessoal, do número de tarefas que estão sendo atribuídas e do número de pessoas envolvidas. No vídeo anterior, mostramos um formato de Gráfico RACI. O modelo abaixo mostra outra maneira de organizar um Gráfico RACI típico.

Vamos examinar mais detalhadamente cada uma das funções e como determinar qual membro da equipe deve ser atribuído a cada função.

### **Responsável**

As pessoas a quem é atribuída a função de "responsável" por uma tarefa são as que realmente estão fazendo o trabalho para concluí-la. Toda tarefa precisa de pelo menos uma parte responsável. É uma prática recomendada tentar limitar o número de Membros da equipe atribuídos à função responsável por uma tarefa, mas, em alguns casos, pode haver mais de um.

Algumas perguntas que devem ser feitas a você mesmo ao determinar qual pessoa ou pessoas devem ser colocadas na função de responsável por uma determinada tarefa são

* A que departamento pertence o trabalho?
* Quem executará o trabalho?

É útil avaliar as pessoas da sua equipe para determinar a função mais adequada a elas. Lembre-se de que talvez seja necessário listar as funções em vez dos nomes, caso algumas pessoas assumam mais de uma função.

Vamos nos aprofundar em nosso exemplo com o Office Green. Nossa tarefa é desenvolver pontos de preço para o projeto, e o analista financeiro concluirá o trabalho para essa tarefa. Portanto, listaremos "Analista financeiro" na função responsável por essa tarefa no Gráfico RACI.

### **Responsabilidade**

A pessoa "responsável" é responsável por garantir que a tarefa seja realizada. É importante ter apenas um indivíduo responsável por cada tarefa. Isso ajuda a esclarecer a Propriedade da tarefa. Em última análise, a pessoa responsável tem Autoridade para aprovar a Entrega da parte responsável.

Para determinar quem deve ser contabilizado como o membro responsável da equipe, considere:

* Quem delegará a tarefa a ser concluída?
* Quem revisará o trabalho para determinar se a tarefa foi concluída?

É possível que você se depare com uma situação em que a parte responsável também seja responsável, mas, sempre que possível, é útil separar essas funções. Garantir que a responsabilidade não seja compartilhada assegura que não haja confusão sobre a quem pertence a propriedade.

Continuando com o exemplo do Office Green, você atribuiu a função "responsável" ao chefe de finanças. O Chefe de Finanças precisa garantir que o projeto fique dentro do Orçamento e tenha lucro, portanto, ele tem a Autoridade máxima sobre os pontos de preço do produto. Portanto, ele precisará aprovar o trabalho do analista financeiro na tarefa.

### **Consultados**

Membros da equipe ou partes interessadas que são colocados na função "consultado" têm informações úteis para ajudar a concluir a tarefa. Não há um número máximo ou mínimo de pessoas que podem ser designadas para a função "consultado", mas é importante que cada pessoa tenha um motivo para estar lá.

Aqui estão algumas maneiras de ajudar a identificar quem é adequado para a Função:

* Qual será o impacto da tarefa?
* Quem fornecerá informações ou feedback à pessoa responsável para ajudar a concluir o trabalho?
* Quem são os especialistas no assunto (SMEs) para a tarefa?

As pessoas consultadas estarão em comunicação frequente e bidirecional com a parte responsável, portanto, é chave garantir que as pessoas certas estejam nessa função para ajudar a realizar a tarefa de forma eficiente e correta.

Voltando ao projeto no Office Green, temos um analista financeiro "responsável" e um chefe de finanças "responsável". Quem mais precisaria fornecer informações sobre os preços do produto? As decisões e o feedback de quem afetarão diretamente a tarefa? O Diretor de Produção precisará ser consultado sobre o assunto, pois ele supervisiona todas as ofertas de produtos. Essa pessoa terá informações sobre possíveis mudanças no produto e como essas mudanças podem afetar os preços.

### **Informações**

As pessoas identificadas como necessitando ser "informadas" precisam conhecer as decisões finais que foram tomadas e quando uma tarefa for concluída. É comum que muitas pessoas sejam atribuídas a essa categoria e que alguns Membros da equipe sejam informados sobre a maioria das tarefas. Os membros da equipe ou as partes interessadas aqui não serão solicitados a dar feedback, portanto, é chave garantir que as pessoas que estão nesse grupo só precisem de atualizações de status e não precisem fornecer nenhum feedback direto para a conclusão do esforço.

As principais perguntas que devem ser feitas a si mesmo para garantir que você tenha capturado adequadamente os indivíduos na Função "informada" são

* Quem se importa com a conclusão dessa tarefa?
* Quem será afetado pelo resultado?

Agora que você determinou quem é responsável, responsabilizado e consultado na tarefa do projeto Office Green, é hora de determinar quem precisa ser informado sobre a tarefa. Seu analista financeiro definiu os pontos de preço com a contribuição do diretor de produção, e o chefe de finanças aprovou. Agora será necessário informar a Equipe de Vendas sobre os preços finais, pois eles precisarão dessas informações para vender o produto.

### **Principais conclusões**

O Gráfico RACI é uma ferramenta valiosa. Ele pode ajudá-lo a definir e documentar as funções e responsabilidades do projeto, dar orientação a cada membro da equipe e partes interessadas e garantir que o trabalho seja feito de forma eficiente. O Gráfico RACI também pode ajudá-lo a analisar e equilibrar a carga de trabalho da sua equipe. Embora possam ser necessárias muitas revisões para garantir que os Membros da equipe e as partes interessadas estejam sendo colocados nas Funções corretas no Gráfico RACI, fazer esse trabalho antecipadamente ajuda a economizar tempo e a evitar falhas de comunicação mais tarde.

### **Equilíbrio da carga de trabalho**

Há muitas tarefas atribuídas a uma parte interessada? Ao concluir seu Gráfico, é uma boa ideia voltar e registrar o número de Rs atribuídos a cada parte interessada. Isso pode ajudá-lo a identificar a possível sobrecarga de trabalho de um membro da equipe. O uso de um Gráfico RACI para determinar a responsabilidade pelas tarefas pode ajudar a mitigar os Riscos de ponto único de falha (conhecidos como criação de **silos**, em que o conhecimento e a responsabilidade por uma tarefa recaem sobre uma única pessoa) e permitir que você, como Gerente de projeto, delegue tarefas e evite o esgotamento. Manter o equilíbrio da carga de trabalho é uma parte essencial do Gerenciamento de projetos. É fácil cair no padrão de confiar em seus melhores funcionários para manter o projeto em andamento. Mas isso nem sempre é saudável para o projeto ou para a sua equipe. Se achar que não tem as pessoas certas a quem atribuir responsabilidades, dê um passo atrás e avalie sua equipe.

### **Coloque seu RACI em prática**

Depois de criar seu Gráfico RACI, é hora de colocá-lo em prática. Primeiro, será necessário compartilhar o Gráfico RACI com seus Patrocinadores e partes interessadas para obter a adesão e a aprovação. Ao obter a adesão das partes interessadas, você poderá definir expectativas claras para a sua equipe e garantir que todos estejam alinhados quanto às suas responsabilidades.

É possível documentar o reconhecimento dessas expectativas pela sua equipe e pelas partes interessadas por meio do Termo de Abertura do projeto, das notas de reunião e do próprio Gráfico RACI. Pense em uma ocasião em que se esperava que você fizesse algo com o qual não concordava ou sobre o qual não tinha clareza. Essa discordância ou falta de clareza dificultou a realização de seu melhor trabalho, certo? Obter a adesão e verificar continuamente com as partes interessadas e a Equipe é a maneira de evitar essa possível armadilha!

Ao reservar um tempo para garantir que cada tarefa tenha um proprietário identificado com o nível adequado de engajamento, você estará simplificando a comunicação e o processo de tomada de decisões durante o Ciclo de vida do projeto.

### **Quando você deve usar um Gráfico RACI?**

Se estiver se perguntando se deve usar um Gráfico RACI em seu projeto, é uma boa ideia avaliar a complexidade do esforço. Por exemplo, se tiver uma equipe de projeto muito pequena, com um pequeno número de partes interessadas, funções claramente definidas e um cronograma curto, a introdução de um Gráfico RACI poderia atrasar o projeto. Entretanto, projetos maiores, ou mesmo projetos que envolvam um grande número de partes interessadas, podem se beneficiar muito de um Gráfico RACI. É sempre uma boa ideia trabalhar na criação de um Gráfico RACI e avaliar o resultado. Mesmo que acabe não usando o Gráfico RACI, você terá uma melhor compreensão do projeto e seu esforço contribuirá para sua experiência geral no Gerenciamento de projetos.

### Lesson 10 - Por que os projetos fracassam: Erros na iniciaçãoSituação: Traduzido automaticamente do InglêsTraduzido automaticamente do Inglês

Informações:Este item inclui conteúdo que ainda não foi traduzido para o idioma de sua preferência.

Você aprendeu as etapas de planejamento necessárias para preparar um projeto para o sucesso. Mas, apesar de seus melhores esforços, os projetos ainda podem fracassar. Às vezes, os fatores que levam ao fracasso do projeto estão fora do seu Controle. A tecnologia para concluir o projeto não está disponível, por exemplo, ou uma parte interessada decide mudar drasticamente as metas do projeto. No entanto, há fatores que podem levar ao fracasso que estão mais sob seu controle, como não conseguir concluir as entregas do projeto dentro do prazo acordado ou não conseguir cumprir a Visão do projeto das partes interessadas.

Nesta leitura, exploraremos algumas das principais razões pelas quais os projetos fracassam e examinaremos como os passos em falso durante a fase de Início podem levar ao fracasso do projeto.

<figure><img src="https://d3c33hcgiwev3.cloudfront.net/imageAssetProxy.v1/ENcd_3I_TxiXHf9yP58YCA_bdbf4b50d1d84f7ab9a9841bdf147581_Screen-Shot-2021-04-13-at-9.53.42-PM.png?expiry=1780265087701&#x26;hmac=xovmfacAgaoM1M5irQKKNMc-_NmnVMPEJ_hhh-fyc7k" alt="Imagem de uma pessoa com um ponto de interrogação perto da cabeça"><figcaption></figcaption></figure>

### **Expectativas pouco claras**

Você deve se lembrar das perguntas que precisa responder no início da fase de iniciação do projeto, incluindo:

* Qual é o objetivo final?
* Quais são as entregas e o Cronograma esperados?
* Qual é o Orçamento?
* Quem são as partes interessadas?

Não dedicar tempo no início de um projeto para fazer perguntas essenciais, documentar decisões e entender o verdadeiro escopo do projeto pode levar ao fracasso. Afinal, sem instruções, você nunca chegará ao seu destino.

### **Expectativas irrealistas**

Todos nós gostamos de impressionar nossos gerentes, mas, às vezes, concordamos acidentalmente com expectativas irrealistas e preparamos nossos projetos para o fracasso desde o início. Por exemplo, se a expectativa é de que um projeto leve duas semanas devido ao nível de detalhe e esforço necessários, mas tentamos concluí-lo em uma semana, não teremos os recursos disponíveis para cumprir o Cronograma consolidado. Isso provavelmente resultará em problemas de qualidade. É importante entender os Requisitos de um projeto antes de concordar com qualquer prazo. AS como prática recomendada, não se comprometa com datas firmes ao iniciar o projeto para evitar a definição de expectativas irrealistas. Você terá mais informações e poderá gerenciar melhor as expectativas na Fase de planejamento.

### **Comunicação incorreta**

A comunicação clara é a chave. Se as informações não forem comunicadas em tempo hábil, não incluírem informações pertinentes (riscos, decisões tomadas, Mudanças de escopo, etc.) ou não forem enviadas às partes interessadas corretas, você pode estar se preparando para o fracasso. A realização de uma Análise das partes interessadas e a utilização de um Gráfico RACI para entender quais partes interessadas devem ser mantidas informadas ou consultadas é um ótimo começo para a criação de uma Estratégia de comunicação eficaz.

Como Gerente de projetos, você não precisa necessariamente atender aos estilos de comunicação exclusivos de todos, mas precisa definir expectativas sobre como a comunicação ocorrerá. Ao iniciar um projeto, certifique-se de dedicar algum tempo para entender as necessidades de comunicação da sua equipe e das partes interessadas. Algumas pessoas não gostam de e-mails e preferem conversar por telefone, outras preferem se comunicar por escrito e outras preferem reuniões presenciais. Um sistema de comunicação sólido incorpora todos esses métodos. Defina as expectativas para a sua abordagem de comunicação com antecedência para que você, os Membros da equipe e as partes interessadas tenham um entendimento claro de como todos se comunicarão.

### **Falta de recursos**

Os recursos incluem os membros da equipe, o orçamento e os materiais. Infelizmente, sem o planejamento adequado, seus recursos podem ser rapidamente sobrecarregados ou esgotados. Às vezes, os Gerentes de projetos não levam em conta o fato de que os Membros da equipe estão fazendo malabarismos com várias tarefas e talvez não consigam dedicar o tempo necessário para concluir todas as tarefas atribuídas corretamente e no prazo. Ou os Gerentes de projetos podem não perceber que um conjunto específico de habilidades é necessário para concluir determinadas tarefas. É fundamental garantir que os Membros da equipe certos estejam disponíveis no momento certo.

Outro erro comum é calcular incorretamente as despesas do projeto. Por exemplo, imagine que você tenha um orçamento do projeto de US$ 10.000. Se seu projeto requer US$ 10.000 para materiais e você também precisa enviar e instalar esses materiais, então não terá dinheiro suficiente para concluir seu projeto. Esclareça suas necessidades de recursos e confirme a disponibilidade deles com a liderança desde o início para evitar atrasos ou problemas no decorrer do projeto.

### **Aumento do escopo**

O escopo fornece um framework abrangente do que está e do que não está incluído no trabalho e nas entregas do projeto. A definição do escopo na fase de Início ajuda a identificar os recursos necessários, o custo associado a esses recursos e o Cronograma necessário para concluir o trabalho. Às vezes, os projetos fracassam porque o escopo do projeto cresce e os impactos no escopo não são capturados.

Por exemplo, imagine que você receba um projeto que originalmente inclui três entregas. Durante o curso do projeto, uma parte interessada solicita a inclusão de mais duas entregas, mas não são feitas mudanças no Cronograma, Orçamento do projeto ou Membros da equipe para refletir o impacto do aumento do número de entregas. Como Gerente de projetos, quando as entregas mudam, é preciso ter certeza de que está capturando o impacto potencial dessas mudanças no cronograma, no orçamento e na qualidade. É por isso que é tão importante certificar-se de que tudo esteja documentado na fase de Início. Tenha um plano de como lidar com o Aumento do escopo, caso ele ocorra, e esclareça quem tem autoridade para aprovar as Mudanças de escopo.

### **Principais conclusões**

Reservar um tempo para esclarecer as expectativas - especialmente em relação aos métodos de comunicação, Disponibilidade de recursos e escopo - durante a fase de Início aumentará as chances de sucesso do seu projeto. Mesmo que você siga essas práticas recomendadas, é possível que ainda assim ocorra um fracasso. Lembre-se de que, em cada fracasso, há a oportunidade de aprender, crescer e fazer melhor da próxima vez.

Para ler mais sobre as Lições aprendidas com projetos que fracassaram, confira este artigo: [Sete Lições Aprendidas com um Projeto Fracassado](https://project-management.com/7-lessons-to-learn-from-a-failed-project/)

### Lesson 14 - Propostas de projetos e cartas 101

​Olá e bem-vindo de volta. ​Anteriormente, discutimos o valor da ​documentação no gerenciamento eficaz de projetos. ​Agora, vamos falar sobre dois tipos comuns de ​documentação que você pode usar para acompanhar os detalhes ​e manter suas partes interessadas informadas. ​São eles: a proposta do projeto ​e o regulamento do projeto. ​Uma proposta de projeto é uma forma de ​documentação que vem ​logo no início do projeto. ​O objetivo deste documento é ​convencer as partes interessadas de que um projeto deve começar. ​E, normalmente, um líder organizacional sênior ​cria a proposta.\

Independentemente ​do formato ou do público, ​criar um plano de projeto é a ​melhor prática para garantir que todos ​concordem sobre como seguir em ​frente antes de entrar na fase de planejamento. ​O estatuto do projeto é um documento vivo.\
​Isso significa que ele pode evoluir à medida que o projeto avança. ​Como gerente de projeto, ​você analisará e refinará ​o regulamento durante todo o processo. ​Agora que você sabe mais sobre ​o valor de uma carta de projeto, ​é hora de aprender como criar uma. ​Encontre-me no próximo vídeo para começar!

**Etapa 2: Escreva um resumo executivo**

Em **Resumo executivo**, escreva de 1 a 3 frases descrevendo o objetivo e os resultados desejados do projeto.

Por exemplo, se estivesse escrevendo um Resumo executivo para o projeto Plant Pals como um todo, ele poderia dizer:

_"Nosso plano é criar um serviço que ofereça aos clientes de alto volume plantas pequenas e de baixa manutenção que possam se desenvolver em um ambiente de escritório."_

Seu resumo para a carta do plano de Operações e Treinamento deve seguir um formato semelhante.

**Etapa 3: Preencha a Meta do projeto**

Na seção **Meta do projeto** da carta, registre a principal meta do projeto do Plano de operações e treinamento. Essa meta deve ser mais detalhada e específica do que seu resumo executivo. Use as informações do cenário para tornar a meta SMAR&#x54;**(Specific**, **Measurable**, **Attainable**, **Relevant**, **Time-bound**).

Por exemplo, uma das Metas SMART para o projeto geral Plant Pals é:

_"Aumentar a receita em 5% até o final do ano, implementando um novo serviço que fornece plantas de escritório para clientes de alto volume."_

_**Observação:** a maioria dos projetos tem várias metas, mas você só precisa de uma para esta atividade._

**Etapa 4: Identificar as entregas do projeto**

Na caixa **Entregáveis**, registre três resultados esperados do projeto. Lembre-se de que essas entregas podem ser resultados tangíveis ou intangíveis do projeto.

Por exemplo, uma entrega tangível do projeto Plant Pals em geral é _"enviar 1.000 plantas para 100 Clientes"_ Um resultado intangível poderia ser _"maior reconhecimento da marca"_

**Etapa 5: Determine o caso de negócios para o projeto**

Na seção **Casos de negócios/ contexto** do projeto, explique o motivo do projeto e como ele contribui para o sucesso geral da empresa. A elaboração de um caso de negócios também dá à sua equipe o contexto necessário para as tarefas do projeto, portanto, não se esqueça de incluir também qualquer informação útil de contexto.

Por exemplo, o caso de negócios para o projeto Plant Pals em geral pode ser: _"Esse é um serviço muito solicitado por nossos clientes e também aumentará a satisfação e a retenção dos clientes."_

**Etapa 6: Preencha as áreas de benefícios e custos (opcional)**

A seção **Benefícios, Custos e Orçamento** já inclui três benefícios do projeto, três áreas de custo e o valor do orçamento. Se desejar, você pode preencher quaisquer benefícios ou áreas de custos adicionais do cenário.

Com relação aos **benefícios**, descreva o que o Office Green espera obter com o projeto. Isso pode incluir benefícios financeiros diretos (por exemplo, receita de vendas), bem como benefícios indiretos (por exemplo, maior confiança do cliente). Lembre-se de que os Benefícios devem apoiar seu caso de negócios.

Com relação aos **custos**, pense em como o projeto completo poderia afetar a empresa. Considere o tempo e os recursos, além de qualquer impacto financeiro.

* _**Observação:**_ não &#xE9;_&#x6E;ecessário atribuir valores monetários a essas áreas de custo neste exercício._ O&#x73;_&#x63;ustos do projeto Plant Pals Operations and Treinamento Plan serão detalhados no próximo curso,_[ _Planejamento de projetos: Putting It All Together_](https://www.coursera.org/learn/project-planning-google/home/welcome)_)_

**Etapa 7: Definir o escopo do projeto (opcional)**

A seção **Escopo e Exclusão** já contém três áreas que estão dentro do escopo e três que estão Fora do escopo do Projeto. Se quiser definir melhor o escopo, você pode preencher itens adicionais dentro e fora do escopo.

**Observação:** O Termo de Abertura do projeto também deve listar os membros da sua equipe de projeto. Essa seção foi preenchida para você.

**Etapa 8: Determinar como medir o sucesso**

Na seção **Medição do sucesso**, liste dois exemplos de Critérios de sucesso que podem ajudá-lo a determinar quando o projeto atingiu sua meta. Você pode usar os critérios do cenário ou determinar outras maneiras de medir o sucesso do projeto. Lembre-se de que os Critérios de Sucesso devem ser específicos e mensuráveis.

Por exemplo, os critérios de sucesso para a Plant Pals como um todo poderiam incluir _"um aumento de 5% na Receita até o final do ano"_ ou _"um aumento de 5% na satisfação do cliente (de 90% para 95%) três meses após o lançamento"_ Esses dois critérios incluem Métricas que facilitam saber quando o projeto atingiu suas metas.

### Lesson 18 - Use a IA para criar uma carta de projeto

​Imagine que você queira construir uma casa. ​Seu primeiro passo provavelmente não seria ​pegar um martelo e pregos; ​primeiro, você planejaria as coisas. ​Você definiria um orçamento, revisaria as plantas e saberia ​como quer que a casa fique quando tudo estiver pronto. A ​construção de um projeto segue a mesma estrutura. ​Nesse caso, os planos são chamados de carta de projeto. ​Como você aprendeu, um contrato de projeto é um documento formal ​que define claramente o projeto e descreve os ​detalhes necessários para alcançar as metas do projeto. ​As ferramentas Gen IA podem ajudar você a criar um ótimo plano de projeto ​e economizar tempo.\
​Vamos em frente e experimentá-lo. ​Para começar, minha solicitação poderia dizer algo como: ​atuar como gerente de projeto e criar um contrato de projeto ​que inclua as informações abaixo. ​Adicione espaços reservados para qualquer informação que falte. ​Neste exemplo, tenho detalhes sobre meu projeto ​em um documento diferente, incluindo uma descrição ​do projeto, a necessidade comercial, os resultados, as ​partes interessadas do projeto e os critérios de sucesso. ​Vou copiar e colar essas informações no Gemini ​para dar mais detalhes à minha solicitação. ​Incluir detalhes como esses em minha solicitação é importante. ​Não estou apenas digitando uma solicitação.\
​Também estou fornecendo informações críticas ​para a Gemini responder. ​Nesse caso, são informações sobre meu projeto planejado, ​e vamos lá. ​Esta carta de projeto da Gemini ​me dá um bom ponto de partida. ​Ainda há trabalho a ser feito. ​Muitos desses marcadores devem ser expandidos em frases completas ​e preciso acrescentar mais detalhes, ​mas comecei muito bem. ​Lembre-se de que quanto mais informações eu der à Gemini para começar, ​mais completa ela poderá tornar o estatuto do projeto. ​Mas essa saída me dá um ponto de partida sólido.\
​Aqui estão algumas coisas que ​você deve ter em mente ao criar uma carta de projeto com a ajuda de uma ferramenta de IA de geração. ​Primeiro, a geração IA pode criar muito conteúdo muito rapidamente ​e em diferentes formatos. ​Isso pode ser muito útil como gerente de projeto ​quando você precisa criar documentação, ​como um contrato de projeto. ​Em segundo lugar, se você já tiver um modelo ​de carta de projeto de sua preferência, poderá compartilhá-lo ​com a Gemini ou fornecer orientação à Gemini ​sobre o formato da carta de projeto que você gostaria de ver. ​Por exemplo, você pode especificar o número de páginas ​ou seções que deseja incluir. ​Lembre-se de ler as respostas com atenção. ​Se você simplesmente der uma olhada na saída, ela pode parecer boa, ​mas na verdade pode incluir algo que você não pretendia. A ​geração IA pode estar fazendo o trabalho pesado, ​mas você ainda precisa pensar pesado aqui.\
​Lembra da estrutura de prompt que discutimos anteriormente? ​É aqui que o E for Evaluate entra em jogo. ​Além disso, você pode experimentar diferentes solicitações ​alterando o texto e a formatação. ​Essa experimentação ajudará muito a ​melhorar os resultados e a oferecer ​mais opções com as quais trabalhar. ​Esteja disposto a tentar novamente ​e seja deliberado com suas instruções. ​Esse é o I em nossa estrutura para Iterate, ​que é o processo de refinar e melhorar ​suas solicitações e saídas de IA por meio de ciclos repetidos ​de testes e ajustes. ​Você pode refinar ou variar a solicitação para obter ​os resultados mais precisos e úteis e descobrir ​se é possível obter outras respostas de sua preferência. Nesse ​sentido, vamos dedicar um momento ​para nos aprofundar um pouco mais na Iteração.\
​Algumas dicas. ​Ao avaliar sua solicitação, você encontrou alguma área em ​que a saída não estava alinhada às suas expectativas? ​Nesse caso, pode haver oportunidades de fornecer à ferramenta de IA ​orientações mais específicas sobre o que você precisa. ​Lembre-se de que uma ferramenta de IA só pode fornecer resultados ​com base no que você diz para ela fazer, ​então certifique-se de que sua solicitação tenha detalhes suficientes ​para obter uma resposta útil ou pense ​no R em nossa estrutura de solicitação, Referências. ​Você pode dar um exemplo do que você está esperando? ​Fornecer exemplos em suas solicitações ​pode ajudar a ferramenta de IA a entender o que você quer. ​Se você espera encontrar um formato ​ou tipo de análise específico, mostre um exemplo à ferramenta de IA.\
​Outra coisa que você pode fazer é verificar seu fraseado. ​Você foi o mais claro possível? ​Tente dividir suas instruções em frases mais curtas. ​Isso pode ajudar você a melhorar a produção na próxima vez. ​Há partes da saída que você gostou? ​Por exemplo, imagine que a ferramenta de IA lhe deu cinco ideias ​para um brainstorming e você gostou de duas delas. ​Em sua próxima solicitação, explique por que você gosta desses dois ​e peça à ferramenta de IA que forneça ​uma nova lista de ideias com base em seu raciocínio.\
​Você pode até mesmo apontar por que não gostou ​das outras três ideias e pedir ​à ferramenta que leve isso em consideração na próxima vez. ​Então, vamos relembrar nosso exemplo, ​usando o Gemini para ajudar a redigir uma carta de projeto. ​Como poderíamos iterar nesse cenário específico? ​Uma forma pode ser pedir uma solicitação de acompanhamento para fazer com ​que a Gemini use uma linguagem menos técnica, ​ou eu poderia pedir à Gemini que encurtasse ou alongasse ​seções específicas, ou poderia pedir à Gemini que ​ajudasse a tornar o regulamento do projeto mais completo. ​Por exemplo, eu poderia perguntar se alguma informação importante ​está faltando no que fornecemos originalmente ​que criaria uma carta de projeto mais forte. ​Pode ser necessário um pouco de prática ​para obter resultados com os quais você esteja satisfeito. ​Jogar e experimentar com instruções é a melhor maneira de ​descobrir como obter resultados que sejam úteis para você.\
​Às vezes, obter o resultado desejado pode levar algumas etapas, ​e a única maneira de chegar lá é se familiarizar, ​explorar e aprender qual caminho funciona para você. ​Vá em frente e tente criar sua própria carta de projeto.

### Lesson 19 - Utilização de ferramentas para o gerenciamento eficaz de projetos

​Como gerente de projetos, ​as ferramentas são alguns dos recursos mais úteis ​que você tem à sua disposição. ​Eles são essenciais para acompanhar o progresso, ​por isso é importante ​mantê-los em mente durante todo o projeto. ​Vamos falar mais sobre por que as ferramentas são tão ​úteis e por que é importante ​escolher as corretas para suas necessidades. ​Existem muitas ferramentas diferentes ​e você aprenderá mais sobre elas mais tarde. ​Como lembrete, as ferramentas são ferramentas que facilitam o ​gerenciamento de recursos e a organização do trabalho por um gerente de projeto ou equipe. ​Eles são úteis porque podem ajudar você a rastrear ​informações detalhadas sobre todos os tipos de tarefas ​e facilitam a ​comunicação com muitas pessoas diferentes. ​E lembre-se de que a comunicação e o rastreamento eficazes são ​grandes partes das ​responsabilidades diárias de um gerente de projetos.\

Antes de apresentar uma nova ferramenta à sua Equipe, é preciso ter certeza de que essa mudança realmente beneficiará o projeto e garantir que as pessoas envolvidas no projeto compreendam os Benefícios dessa mudança. ## **Recursos essenciais do Sheets para gerenciamento de projetos**

### **Colabore com sua equipe**

O Planilhas Google facilita a colaboração e o compartilhamento de informações. Isso é útil para grupos de trabalho remotos ou para trabalhar com equipes que têm horários diferentes.

Ao compartilhar sua planilha, você pode selecionar uma das seguintes permissões:

* **edição**, que permite que outras pessoas façam edições e alterações diretas no arquivo;
* **comentar**, que permite que outras pessoas adicionem comentários e façam sugestões; ou
* **somente visualização**, que permite que outras pessoas visualizem o arquivo, mas não editem, comentem ou sugiram. Essa é uma boa opção se você não quiser que nenhuma alteração seja feita no arquivo.

Depois de compartilhar a planilha com a sua equipe e conceder a ela permissões de edição ou de comentários, todos podem colaborar diretamente na planilha deixando comentários. Você também pode atribuir uma tarefa ou Item de ação por meio de comentários.

_**Confira estes recursos da Central de Ajuda do Google para saber mais:**_ [Compartilhar e colaborar em arquivos](https://support.google.com/a/users/answer/9305987?hl=en)

### **Formatar sua planilha**

#### **Criar listas**

Para criar qualquer lista no Planilhas, basta rotular cada lista - por exemplo, Nome, Data, Notas ou outros critérios - na **linha do cabeçalho**. (A linha de cabeçalho é a linha superior da planilha.) Em seguida, adicione um item de lista diferente em cada célula abaixo do título da lista. A maioria das listas é organizada verticalmente, mas você pode preferir uma lista horizontal, dependendo dos tipos de itens. _Observação: Você aprenderá a elaborar um Plano de projeto completo e a priorizar tarefas mais adiante neste curso._

#### **Exibir e ocultar conteúdo**

**Congelar linhas ou colunas**

Congelar a linha do cabeçalho (ou coluna para listas horizontais) e formatar os cabeçalhos é uma ótima maneira de destacar os títulos da lista. O congelamento de uma linha de cabeçalho mantém a linha no lugar quando você rola a lista para baixo, para que você sempre possa ver quais são os títulos da lista. Formate os cabeçalhos da mesma forma que faria com o texto em um documento, alterando a fonte, o estilo, o tamanho ou a cor.

**Agrupe e oculte conteúdo relacionado**

O agrupamento de linhas e colunas permite expandir e recolher categorias maiores de dados ou informações com um único clique. Isso facilita a leitura e o gerenciamento da planilha, pois oculta os dados agrupados quando não são necessários, ou os desagrupa e mostra rapidamente quando são necessários.

#### **Adicionar caixas de seleção**

As caixas de seleção são uma maneira rápida e altamente visual de acompanhar o progresso de uma tarefa ou indicar se determinados critérios foram atendidos.

_**Confira estes recursos da Central de Ajuda do Google para saber mais:**_ [Adicionar caixas de seleção a planilhas](https://support.google.com/a/users/answer/9308622?hl=en\&ref_topic=9326428)

### **Organizar dados**

#### **Criar listas suspensas**

Se estiver trabalhando com outras pessoas em uma planilha compartilhada, poderá acabar com respostas ou descrições de dados inconsistentes. Por exemplo, um colega de equipe pode listar sua tarefa como "concluída", enquanto outro a anota como "completa" A adição de uma lista suspensa (também chamada de **Validação de dados**) garante que os dados inseridos na planilha sejam exatamente os que você especificar. Isso também torna muito mais rápido para os outros adicionar dados, pois eles estão selecionando em uma lista predeterminada de opções.

_**Confira estes recursos da Central de Ajuda do Google para saber mais:**_ [Restringir a entrada de dados com listas](https://support.google.com/a/users/answer/9604139?hl=en#zippy=%2Clearn-how)

#### **Adicione um código de cores**

Às vezes, é útil alterar a cor das células e do texto para que você possa ver rapidamente como o projeto está progredindo. É possível adicionar um código de cores à planilha aplicando **a Formatação condicional**. A formatação condicional formata as células de uma determinada maneira se elas contiverem informações específicas. Por exemplo, rastreie o status do progresso como "Não iniciado" em vermelho, "Em andamento" em laranja e "Concluído" em verde.

_**Confira estes recursos da Central de Ajuda do Google para saber mais:**_ [Veja as alterações de dados com formatação condicional](https://support.google.com/a/users/answer/9308962?hl=en\&ref_topic=9327402)

#### **Classificar e filtrar dados**

Grandes conjuntos de dados podem ser difíceis de gerenciar. O Classificar planilhas ajuda a classificar e filtrar dados para limitar o que é visível e encontrar tipos específicos de dados na planilha.

**A classificação de** dados permite que você organize os dados exatamente na ordem em que deseja que eles apareçam, como alfabeticamente, por data ou nível de progresso. **A filtragem** limita os dados que são exibidos e mostra apenas os dados de seu interesse, como tarefas que ainda não foram iniciadas ou itens de orçamento dentro de uma determinada faixa de valores.

_**Confira estes recursos da Central de Ajuda do Google para saber mais:**_ [Filtrar dados em uma planilha](https://support.google.com/a/users/answer/9308952?hl=en)

#### **Adicionar links**

Pode ser útil criar links para outras documentações do projeto ou até mesmo para sites externos em sua planilha. Isso proporciona à sua equipe acesso fácil e centralizado a todos os dados relevantes de que possam precisar. Por exemplo, você pode adicionar um link para o documento de abertura do projeto a partir da planilha de Plano de projeto.

### **Visualização de dados**
